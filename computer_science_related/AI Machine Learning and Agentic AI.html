1. The AI map: one field, two branches, outside parts

Artificial intelligence is the overarching field in computer science where we train computers to do tasks humans are generally good at: recognizing patterns, seeing, hearing voice, handling text. That single sentence is your anchor; everything else today hangs off it. Inside AI sits machine learning, an important subdomain, and ML itself splits into two main branches. Statistical machine learning holds the classic statistical algorithms — linear regression, decision trees, KNN (k-nearest neighbours) — used for classification and regression, which you will meet properly at Stop 3. Deep learning is mainly about neural networks: whenever you use neural networks, you are doing deep learning.

Within neural networks live architectures — CNNs for images, RNNs for sequences, and the transformer, the architecture behind the modern generative and agentic boom. GenAI and agentic AI are not new fields beside AI; they are applications of AI, use cases built mostly on transformers. Finally, note what is AI but not ML: regular expressions powering a human-level text system, rule-based systems, and robotics parts that use no learning at all (robots also deploy trained models, but much of a robot is classical engineering). Learners constantly blur statistical ML with deep learning, or ML with DL; keep the nesting strict — AI contains ML, ML contains both branches — and the jargon ahead stops colliding.

Key definitions.
Artificial intelligence (AI)
The overarching field training computers on human-easy tasks like seeing and language. Detail: it is the umbrella — rules, robots, and learning all live under it, from spam filters to poem writers.
Machine learning (ML)
The AI subdomain where programs learn patterns from data instead of fixed rules. Detail: training replaces hand-written logic, but it demands data plus a clear task (Stops 2–3).
Statistical ML
The branch using classic algorithms such as regression, trees, and KNN. Detail: shines on tidy tables with clear features — the session's spam and price examples live here.
Deep learning (DL)
The branch using neural networks; every neural net counts as deep learning. Detail: stacks neuron layers that invent their own features from raw pixels or text — at the cost of far more data and compute.
Transformer
The neural architecture behind modern generative and agentic systems. Detail: an architecture, not a product — GPT, Gemini, and Claude are all transformer-based applications of it.
Procedure
  1. Say the nesting aloud: AI contains ML; ML holds statistical and deep branches.
  2. File transformer under architectures, and GenAI beside applications.
  3. Name one AI ingredient with no learning: regex, rules, or robot hardware.
Obvious example. A regex ticket-router matching order numbers at human accuracy with zero learning.
Counter-intuitive example. A robot arm: its vision model learned, but its gears and timing loops never did.
Edge case. GPT writing poems: an application of AI, not a third field beside ML.
Analogy card. A library (AI) with a learning wing (ML), two reading rooms (statistical, deep), a star atlas everyone cites (transformer) — plus a stationery shop outside that still serves readers (regex, rules).
What people get wrongThat ML and DL are synonyms. DL is one branch inside ML; statistical ML is the other.
Why this matters. Every later term docks at exactly one place on this map.

2. Learning from examples: spam, squares, training, inference

How does Google sort spam? Look at a junk mail: urgency phrases, lucrative offers, a suspicious sender ID. Now imagine no algorithm at all — a hired spam detector studies 10,000 old spam and 10,000 good mails, and collects exactly those patterns in their head. Training a program works the same way: feed thousands of labelled mails, and it learns to judge fresh arrivals. The squares table makes the mechanism visible: inputs 1, 2, 3 give 1, 4, 9, so input 4 must give 16 — you extracted the squaring pattern from examples, and a program does likewise. Machine learning therefore runs in two phases: training, where the program studies input-output pairs, and inference, where the trained model predicts on new inputs.

The famous three-item diagram locks this in. Any task has an input, an output, and the equation (logic) between them. Traditional programming hands the computer input plus equation — your code, say y = x squared — and receives output. ML training flips it: hand over input plus output, and the computer derives the equation, storing that logic as a model file on disk. At inference time the model takes fresh input and returns output like any program. So machine learning means training machines on data to predict without explicit programming — no hand-written rules, just patterns noticed in examples. Remember this flip; it explains every tool you will meet later.

Key definitions.
Training
Showing the program thousands of input-output pairs so it extracts patterns. Detail: the 10,000-spam / 10,000-good-mail study phase — the quality and balance of examples decide everything downstream.
Inference
Using the trained model on a fresh input to get a prediction. Detail: the live phase — one fresh mail in, one verdict out; no learning happens here.
Model
The stored equation or logic learned during training, saved on disk. Detail: weights plus structure — the "equation" the session names; you can store, copy, version, and reload it.
Explicit programming
Hand-writing rules; ML replaces it with learned patterns. Detail: y = x² typed by hand versus squares discovered from rows — the Stop 2 flip.
Procedure
  1. Spot the patterns a human would note (sender, wording, urgency).
  2. Feed input-output pairs; let training derive the equation into a model.
  3. At inference, send fresh input to the model and read the prediction.
Obvious example. Spam filter trained on 20,000 mails judging tomorrow's inbox.
Counter-intuitive example. You teaching yourself squares from three rows — human training, same loop.
Edge case. A spammer inventing new phrasing the model never saw — inference under drift.
Analogy card. An apprentice sorter studies sorted baskets for a week (training), then sorts live parcels alone (inference).
What people get wrongThat the program contains hand-written spam rules. It contains learned weights; nobody typed the patterns.
Why this matters. Training versus inference explains cost, failures, and retraining.
Leads to Stop 3: what kinds of answers can training produce?
Memory: I-O-E flip — code gets I+E, learning gets I+O
Recall prompt. State the three items and which two each approach receives, then reveal.
Input, output, equation. Traditional: input + equation → output. ML training: input + output → equation (model).

3. Task families: classify, predict numbers, label or not

Statistical ML solves two big task types. Classification maps an input to fixed categories: spam or not, cat or dog, damaged car or clean one. Two outputs make binary classification; more — business, sports, technology, health in Google News — make multiclass. Regression instead outputs any number: Zillow's Zestimate trains on sold homes (bedrooms, area, age, price), then prices a new listing at, say, 925K, where 923K or 921.45K were equally possible. Discrete labels versus open numbers — that single contrast tells the families apart, and the session lists everyday problems under each so you can sort new tasks on sight.

Orthogonal to that sits supervision. Training pairs are X (input) and Y (output, also called the label). Working from labelled pairs is supervised learning — but labelling costs effort, tagging thousands of mails. Unsupervised learning skips labels: hand the kid toys plus two blank buckets and let them group by colour, vehicle type, or size — patterns without instruction. Industry uses both: ATL's 55 staff scatter legal papers, invoices, and requirements across OneDrive, and clustering regroups them by wording and format; Bloomberg clustered earnings estimates and flagged loners as outliers with DBSCAN (alternatives: K-Means, hierarchical clustering), while random forest, XGBoost, trees, and linear regression stay supervised. Python tooling closes the stop: Python itself, pandas and numpy for cleaning, matplotlib and seaborn for plots, Jupyter for development, XGBoost and scikit-learn for training.

Key definitions.
Classification
Mapping inputs to fixed categories; binary for two, multiclass for more. Detail: spam-or-not (binary) and news sections (multiclass) are the session's anchors — answers always come from a closed list.
Regression
Predicting any number, such as a home price. Detail: the Zestimate — 925K today, 923K tomorrow; any number on the line is a legal answer.
Label (Y)
The known output in a training pair; input is X. Detail: the "spam" tags on old mails — labelling thousands of pairs is the hidden cost of supervision.
Supervised learning
Learning from labelled X-Y pairs, paying labelling effort. Detail: a teacher with an answer key — trees, forests, and XGBoost all learn this way.
Unsupervised learning
Finding structure in unlabelled data, e.g. clustering and outliers. Detail: no answer key — the toy buckets, the OneDrive regrouping, and the Bloomberg loners.
Algorithm gallery — one-line working pictures.
Linear regression
Draws the best straight-line fit through past points; reads new X values off that line. Regression. Detail: predicts continuous numbers only — never pick it for fixed labels.
Decision tree
Branches through yes-no questions (offer wording? sender odd?) down to a verdict. Both tasks. Detail: readable — you can trace each question path, which is why teams start here.
Random forest
Grows many trees on varied samples and lets them vote; steadier than any single tree. Detail: each tree sees a different slice, so majority vote smooths individual quirks.
XGBoost
Builds trees in sequence, each one fixing the previous errors; a champion on table data. Detail: slow to train, fast to serve — the default weapon for fraud-style tables.
KNN (k-nearest neighbours)
Labels a newcomer by majority vote of its k closest past examples. Detail: almost no training phase — the data itself is the model, and k sets the smoothing.
K-Means
Picks k centers, assigns every point to the nearest, then re-centers until settled. Detail: you must choose k first, and results depend on the starting centers.
DBSCAN
Grows dense neighbourhoods into clusters; loners in thin regions are flagged as outliers. Detail: finds its own group count — the Bloomberg earnings screen for odd estimates.
Hierarchical clustering
Nests groups inside groups, like folders inside folders, bottom-up or top-down. Detail: draws a family tree (dendrogram) you can cut at any height for your groups.

The session names these algorithms; the one-liners are standard working pictures so the names stick.

Toolbox — what each tool does.

The language almost all AI code is written in. Detail: readable syntax plus a library for everything — the session calls it the language of AI.
pandas / numpy
Table handling and fast number-crunching for cleaning and exploration. Detail: pandas frames the tables you inspect; numpy crunches the arrays underneath.
matplotlib / seaborn
Plots and charts for seeing distributions before modelling. Detail: histograms and heatmaps catch the skew and gaps that training would choke on.

  2. Ask: do I have Y labels? Supervised — else cluster or flag outliers.
  3. Pick the tool: scikit-learn or XGBoost in Jupyter over pandas frames.
Obvious example. Spam versus good mail — binary classification, supervised.
Counter-intuitive example. Toy buckets with no instructions beating fixed buckets for discovering colour groups.
Edge case. One weird earnings estimate in no cluster — an outlier worth a human look.
Analogy card. Labelled jars (supervised) versus a mixed toy box sorted by whatever pattern emerges (unsupervised).
What people get wrongThat clustering needs correct answers first. It needs none — groups emerge from similarity.
Why this matters. Two questions route every ML task to the right method.

4. Deep learning: the koala classroom and when to use it

Fraud rows and cat photos both classify, yet their data differs utterly. Fraud tables are structured — rows and columns like vendor, amount, location — while an image is unstructured pixels, like text and video: no tables at all. Those columns are called features, and statistical methods such as trees and XGBoost thrive on tidy features but stall on pixels. Your brain shows the alternative: spotting a cat via round eyes, pointy ears, whiskers — nonlinear, parallel, tolerant of shifted positions, where no rigid pixel rule could survive. Neural networks copy that trick, and the koala classroom makes them concrete: students who never saw a koala split the job — Mike scores eyes, Mohan noses, Shakib ears, each 0 to 1 — then Serena fuses them into a face score with a formula weighting the distinctive nose (0.79 on a koala, 0.15 on a lion), while Ji and Chen feed Nidhi's body verdict, and Sergey decides, weighting the face.

Each student is a neuron; Mike's group is the input layer, Serena and Nidhi a hidden layer, Sergey the output. Training is the classroom loop: random guesses, Sergey's check with the supervisor outside, error carried backwards — backward error propagation, or backpropagation — adjusting weights over thousands of images via derivatives, until paths light up like a Delhi-to-Bangalore route on Google Maps. Expect Chihuahua-versus-muffin mistakes; humans stumble there too. Choose sides with three loose criteria: simple structured features favour statistical ML, complex unstructured inputs favour deep nets, and huge data volumes favour deep nets — though big tables sometimes still go deep, so treat these as guidelines and experiment. Architectures come in flavours: feedforward flows one way like a juice machine; recurrent nets loop output back over time like tasting soup while cooking; the transformer — behind all modern GenAI — earns its own later chapter. Build with PyTorch (Meta, popular, beginner-friendly) or TensorFlow (Google, fine-grained control), plus GPUs — millions of records will not train on CPU, locally or rented.

Key definitions.
Feature
One input column or trait, e.g. amount, or an eye shape. Detail: vendor and amount arrive as given features; whiskers arrive as learned ones — nets invent their own where tables cannot.
Structured / unstructured data
Tables with rows and columns versus raw pixels, text, video. Detail: tables arrive already featurized; pixels arrive mute — that gap is what decides the method.
Neuron / layer
One sub-decision unit; input, hidden, and output stages of a net. Detail: Mike the eye-scorer is a neuron, Serena's face group is a hidden layer, Sergey is the output.
Backpropagation
Passing prediction error backwards to adjust weights. Detail: Sergey's supervisor verdict flows back to Mike and Mohan — assigning credit for the mistake via derivatives.
Feedforward / recurrent / transformer
One-way flow; time-looped flow; the modern attention architecture. Detail: single pass, tasting-loop, parallel attention — the field guide below expands each.
Architecture field guide.
CNN (convolutional neural network)
Slides small filters across images to catch edges, then textures, then shapes; pooling shrinks the maps as it climbs. The image specialist. Detail: early layers fire on edges, deeper ones on ears and wheels — tolerant to shifts in position and scale by design.
RNN (recurrent neural network)
Carries a hidden state forward step by step, so each decision remembers earlier inputs. The sequence specialist: text, speech, time series. Detail: reads step t with memory of everything before — the soup-tasting loop laid over time.
Transformer
Weighs (attends to) the most relevant parts of the whole input at once, in parallel — the base of GPT and modern GenAI. The session postpones full depth to a later lecture; this picture is enough to place it. Detail: attention scores every part against every other part simultaneously — that parallelism is why it scaled past RNNs.
GPT (Generative Pre-trained Transformer)
Pre-trained, generative, transformer-family model — e.g. GPT-3, GPT-4, GPT-4o, GPT-4.1 mini. Detail: pre-train on the world once, then generate on demand — the name is literally the recipe.
PyTorch / TensorFlow
PyTorch (Meta) reads friendlier for beginners; TensorFlow (Google) gives finer-grained control. Both need GPU muscle for big data. Detail: prototype in PyTorch's eager style, ship wherever your team lives, and rent GPUs either way for million-row training.
Procedure
  1. Check structure: tables point to statistical ML, pixels to nets.
  2. Count samples: huge volumes push toward deep learning plus GPU.
  3. Match shape over time: one pass, loops, or transformer base.
Obvious example. Fraud rows through XGBoost — tidy features, fast win.
Counter-intuitive example. A giant tabled dataset still choosing a neural net after testing both.
Edge case. Chihuahua versus muffin — the net fails exactly where people hesitate.
Analogy card. Students as neurons, supervisors as labels, report cards as weights — the classroom is the network.
What people get wrongThat nets memorize pixel positions. They learn shift-tolerant features, which is the whole point.
Why this matters. This stop explains every modern model you will touch next.

5. Generative AI: making new things, and its limits

Say generative AI and most people picture ChatGPT: resumes, vacation plans, a poem about samosas. The category stretches further — describe an image and receive one, or prompt Sora with a translucent octopus climbing a mountain, or a dog reading a book, and receive video that looks real yet never happened. The definition is one line: AI whose objective is generating new content — text, image, audio, video. Behind the scenes sit named models: GPT in versions 3, 4, 4o; Meta's open-source Llama on meta.ai; Google's Gemini; Anthropic's Claude; DALL-E and Stable Diffusion for images; AudioGen and Google's MusicLM for sound; Sora for video.

Everything before ChatGPT was traditional AI: spam filters, image classifiers, price predictors — classification and regression from the earlier stops, still solved with statistical and deep models, still the right call where lightweight suffices. Six contrasts separate the eras. Purpose: analyse and decide versus generate. Output: labels and numbers versus fresh paragraphs. Models: trees, regression, SVMs (plus plain deep nets) versus LLM-based, GANs, diffusion. Training: labelled supervision versus pre-training on massive internet-scale text. Humanlike range: narrow versus poet-capable. Tooling: XGBoost and scikit-learn versus LLM platforms. Your companion lesson Introduction to Generative AI continues exactly here — content, code, search, and summary jobs in daily tools.

Key definitions.
Generative AI (GenAI)
AI whose objective is producing new content, not labels. Detail: poems, portraits, clips — if the output did not exist before the prompt, you are here.
Traditional AI
Classification and regression systems, still best where lightweight wins. Detail: spam filters and Zestimates still run here — cheaper, faster, and easier to audit than any giant model.
Pre-training
Learning from massive datasets such as internet text and books. Detail: months of reading once, reused for everything after — scale of reading is the capability.
Diffusion / GAN models
Model families behind many image and media generators. Detail: diffusion denoises static into pictures step by step; GANs pit a forger against a detective until fakes pass.

6. Large language models: the parrot that read the world

The modern revolution runs on large language models. Build intuition with Buddy, Peter Panda's parrot: superb mimic, sharp memory, zero comprehension. Hearing hunger talk ending in biryani, Buddy rates biryani, cherry, food far above bicycle or book — statistical probability plus randomness choosing next words from past chatter. Such a system is a stochastic parrot (stochastic means ruled by probability), and a language model is its software cousin: neural networks predicting next words, as when trained on movie Wikipedia it completes movie sentences, or Gmail autocompletes your mail. Scale turns the parrot large: grant Buddy every town's conversations — neighbours, schools, universities worldwide — and suddenly history answers, nutrition advice, and poems all flow. Real LLMs train on Wikipedia, news, and books at that breadth, holding trillions of parameters that capture deep language patterns; ChatGPT runs GPT-3 or GPT-4, with PaLM 2 and LLaMA as peers.

Raw prediction alone would stay feral, so a second ingredient civilizes it: RLHF, reinforcement learning with human feedback. Buddy absorbs abusive parents' talk and repeats an iron-rod threat to a toddler; Peter then grades multiple answers per question as toxic or not until the parrot cleans up — exactly how OpenAI's human workforce detoxified ChatGPT. Close with the boundary the session stresses: LLMs hold no subjective experience, emotions, or consciousness; they run on training data, however fluent. The analogy sketches intuition only — machinery differs in detail — but it predicts behaviour well: probabilities first, human grading second, confident tone throughout, understanding never.

Key definitions.
Language model
A program predicting likely next words from past text. Detail: Gmail finishing your sentence is the everyday specimen — probabilities, not understanding.
Stochastic parrot
A mimic fluent in probabilities with no comprehension. Detail: biryani-beats-bicycle is statistics, not appetite — the session's core warning about every fluent model.
Large language model (LLM)
A language model trained at world scale, e.g. GPT, Gemini, Claude, Llama. Detail: the same parrot with a world-scale library — trillions of tuned knobs capturing deep language patterns.
Parameter
One learned value inside the net; LLMs hold trillions. Detail: a single weight among trillions — capability climbs as counts and data climb together.
RLHF
Human grading of answers to steer the model safer. Detail: Peter grading Buddy's answers is the loop in miniature; OpenAI's workforce ran it at industrial scale to detoxify ChatGPT.
Procedure
  1. Picture next-word bets from past text — the parrot core.
  2. Multiply the reading to world scale — that largeness.
  3. Add human grading — RLHF — and expect fluency without feeling.
Obvious example. Gmail finishing your sentence from mail patterns.
Counter-intuitive example. A model writing a fine poem while understanding nothing of longing.
Edge case. Toxic-town chatter surfacing as threats until graders intervene.
Analogy card. Buddy the parrot: world-travelled ears, probability beak, human editors.
What people get wrongThat fluency proves comprehension. It proves pattern density plus grading.
Why this matters. This mental model predicts hallucinations and toxicity before they bite.
Leads to Stop 7: what you can build once parrots take tools.

7. From answering to acting: workflows, tools, agents

Following Anthropic, LLM applications split into workflows and agents, and ATL Technologies' HR helper climbs the ladder live. Rung one, the RAG chatbot: policy PDFs stay private, ChatGPT cannot know them, so retrieval augmented generation lets an LLM (Claude, GPT) read the files and answer vacation-day and sick-leave questions — reactive Q&A, hence a workflow, not an agent. Rung two, the tool-augmented chatbot: Mohan Sharma logs in, asks his own leave balance, and files two days off inside the chat. Policy text plus HR-system APIs exposed as tools — a brain handed a screwdriver — supplies identity, context, and action. Still a workflow: useful, yet narrow and autonomy-free. (Your companion lesson's RAG and agent modules replay this same ladder in product terms.)

Rung three earns the name agent: "prepare Sara's maternity cover" or "onboard Monday's intern" triggers goal-oriented multi-step planning — checklist, Outlook welcome meeting with generated text, HRMS profile, IT tickets for Wi-Fi and Slack, laptop and ID orders — a reasoning model sequencing tools, knowledge, and memory, deciding and doing without step-by-step orders. Traits to memorize: goal-first planning, autonomous decisions, real executed actions. One agent perceives, decides, and acts; agentic AI is the system holding one or more such advanced agents. Builders choose code frameworks (Agno, Google's ADK, OpenAI toolkits) or drag-and-drop n8n: an onboarding trigger feeds an agent (Claude chat model, Postgres memory, Jira and laptop tools) that branches managers into their Slack channel. GenAI is both the application family above and a component inside — the LLM passages that draft and extract — while deep-research mode on the same ChatGPT that answers simply turns agentic: browsing, calling tools, reviewing and correcting toward a goal. Reactive answers versus proactive acting — that is the whole difference.

Key definitions.
RAG
Letting an LLM answer from your private files at query time. Detail: vacation-day answers cite ATL's PDFs, never training memory — reactive, grounded, and private.
Tool (for LLMs)
An API exposed so the model can look up or change systems. Detail: the HRMS leave API plus Mohan's login turns a balance question into a filed application.
Workflow
An LLM path with fixed steps: RAG answers, tool-augmented chats. Detail: fixed rails — the same steps every run, with no goal planning of its own.
AI agent
One component perceiving, deciding, and acting toward a goal. Detail: perceives the onboarding request, plans the steps, then books meetings and files tickets itself.
Agentic AI
A system of one or more agents planning multi-step work autonomously. Detail: agents plus memory plus tools — the whole n8n canvas, never a single node.

FAQ

Questions learners always ask

Are ML and deep learning the same?

No. ML is the field; deep learning is its neural-network branch, beside statistical ML. See Stop 1.

Where is the model in training versus inference?

Training produces it from pairs; inference consults it for fresh inputs. See Stop 2.

When do I pick deep learning over statistical ML?

Unstructured inputs, complex features, or huge volumes push deep; tables with clear columns stay statistical. Test both. See Stop 4.

Do LLMs understand what they write?

No — probabilities plus grading yield fluency without experience or consciousness. See Stop 6.

How do K-Means and DBSCAN differ?

K-Means needs the group count up front and centers each group; DBSCAN grows dense regions and names loners outliers. See Stop 3.

PyTorch or TensorFlow for a beginner?

The session calls PyTorch friendlier and TensorFlow finer-grained; pair either with a GPU for big data. See Stop 4.

Is a tool-using chatbot already an agent?

Not yet. Goal planning plus autonomy promote it; tools alone keep it workflow. See Stop 7.
