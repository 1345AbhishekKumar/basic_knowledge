Lesson 01 · Transformer Architecture

Attention and the Transformer Block

One operation, derived properly, then placed inside the block that repeats sixty times to make the models you use every day.

A transformer is a stack of identical blocks. Each block does two things: it mixes information across positions, then it processes each position independently. The first job is attention. The second is a small feed-forward network.

That is the whole architecture. Everything else — residuals, layer norms, positional encodings, multi-head splits, the KV cache — exists to make those two operations trainable, expressive, or cheap enough to run.

This lesson derives attention from the problem it solves, places it in the full block, and then maps the landscape of related topics so you know what lies in each direction.

Part I · The problem attention solves

Before 2017, sequence models were recurrent. They read a sentence one token at a time, carrying a hidden state forward. Two problems followed, and both were fatal.

It is inherently sequential

Token 500 cannot be processed until token 499 is done. On hardware built for parallelism — thousands of cores that want to do the same operation on different data simultaneously — this wastes almost all of it. Recurrent networks run at a fraction of what the hardware can deliver, and no amount of engineering fixes that, because the dependency is in the math.

It forgets

Every token's information is squeezed through the same fixed-size hidden state. By the time you reach the end of a long passage, the beginning has been overwritten. The hidden state is a bottleneck, and it does not grow with the input.

Attention's move is to delete the recurrence entirely. Let every token look at every other token directly, all at once. No hidden state, no sequential dependency, no fixed-size bottleneck.

The cost of that move is the subject of the rest of this lesson. It is a real cost, and it is why the architecture looks the way it does.

Working definition

Attention computes a weighted average of value vectors, where the weights come from how well each value's key matches a given query.

That sentence is the entire mechanism. The rest of this part unpacks it.

Part II · Queries, keys, and values

The vocabulary is borrowed from information retrieval, and the analogy is exact. Imagine a lookup table where you search by similarity rather than by exact match.

You arrive with a query — what you are looking for. Every entry in the table has a key — what it is about. You compare your query against every key and get a relevance score. Then, instead of returning the single best match, you return a weighted blend of all the values, weighted by relevance.

In a transformer, every token plays all three roles at once. Each token's embedding is projected through three learned matrices — W_q, W_k, W_v — producing a query, a key, and a value for that token. The token's query is then compared against every token's key, including its own.

Those three matrices are learned during training. Nothing about the Q/K/V split is hand-designed; it is simply enough capacity for the model to learn three different useful projections of each token.

Part III · The math

Everything above, in one line:

Attention(Q, K, V)=softmax(QKT/√dk)V
Scaled dot-product attention · Vaswani et al. 2017, §3.2.1

Read it left to right and it is the diagram you just looked at:

QKT
Every query dotted with every key. Produces an n × n matrix of raw compatibility scores — one number for each (query, key) pair.
/ √dk
Divide by the square root of the key dimension. Without this, dot products grow with dimension, softmax saturates, gradients vanish, and training stalls.
softmax( · )
Turn each row of scores into a probability distribution. Values become positive and sum to one across the row — these are the attention weights.
· V
Matrix-multiply the weights by the values. Each output vector is a weighted average of all value vectors. This is the only place information actually moves between tokens.

Why the scaling matters

Suppose dk = 64 and the entries of q and k are independent with mean 0 and variance 1. Then their dot product is a sum of 64 such terms, so it has mean 0 and variance 64 — standard deviation 8. Scores routinely land in the range ±30.

Feed that into softmax and the largest score dominates completely. If one score is 20 and the rest are near 0, softmax returns approximately [1, 0, 0, …]. A near-one-hot softmax has a gradient close to zero almost everywhere, which means the model stops learning from that head. Nothing about the architecture breaks; it just silently stops training.

Dividing by √64 = 8 pulls the variance back to 1, keeps the softmax in a range where it produces a genuine distribution rather than a hard argmax, and keeps gradients alive. This is why the formula is called scaled dot-product attention. The scale is not cosmetic, and it is a good illustration of the whole design philosophy: every term in this architecture is load-bearing.

The scaling factor is an approximation. It keeps variance constant under the assumption that q and k entries are independent and unit-variance. Real trained models do not satisfy that exactly — but the correction is good enough that nobody has replaced it in eight years.

Two properties that fall out immediately

Attention is permutation-invariant. Shuffle the input tokens and you shuffle the outputs identically — the operation has no notion of order. The matrix QKT does not care which token is first. This is why positional encoding exists, and why it is not optional.

Attention is quadratic in sequence length. The n × n score matrix means doubling context quadruples the work. This is the real reason long context is expensive, and the reason every efficient-attention variant since 2017 has attacked this term specifically.

Part IV · Multi-head attention

Averaging values with a single set of weights forces the model to make one choice per token about where to look. That is limiting. Consider:

"The trophy would not fit in the suitcase because it was too large."

The word "it" needs to attend to "trophy" to resolve the reference — but it also needs to attend to "large" to know which way the ambiguity resolves. And "large" itself needs to know it modifies "trophy" rather than "suitcase". A single attention distribution is a single set of weights; it can be sharp on one of these and diffuse on the others, but it cannot commit to several different relations at once.

Multi-head attention runs h attention operations in parallel — typically 8 to 32 heads — each with its own W_q, W_k, W_v. Each head works in a lower-dimensional subspace of size dmodel / h, and each produces its own output. The outputs are concatenated and projected through a final W_o back to the model dimension.

The total parameter count is roughly the same as single-head attention at full width, because each head is narrower. What changes is expressiveness: the model can now represent several different relationships between the same pair of tokens.

Different heads do specialise. When people visualise trained transformers, the recurring patterns are:

  • Positional heads that attend strongly to the immediately preceding token, tracking local word order.
  • Syntactic heads that link verbs to their subjects or prepositions to their objects.
  • Coreference heads that resolve pronouns to their antecedents.
  • Rare-token heads that dump attention onto a small set of separator or punctuation tokens when nothing useful is available.
  • Attention sinks that park almost all weight on the first token, acting as a no-op the model can fall back on.

That last one is worth knowing about because it explains a real behaviour: models behave strangely when you remove the first token from a long prompt, because you have removed the sink they were relying on.

A caution about interpretability

Attention weights are not explanations. A high weight from token A to token B means the model routed information along that edge — it does not mean the model "used" B to decide about A in any way you can read off. Attention heads are redundant, and ablating one often changes nothing measurable.

Treat attention visualisations as a debugging tool, not as evidence about reasoning. This is one of the most common mistakes in the field.

Part V · The full transformer block

Attention on its own is not a transformer. It is one sub-layer inside a block, and the block is what gets repeated. A block is:

  1. Layer norm on the input
  2. Multi-head self-attention
  3. Residual add — add the sub-layer output back to the input
  4. Layer norm again
  5. Feed-forward network — a small MLP applied to each position
  6. Residual add again

Then that whole sequence is stacked N times — 12 for GPT-2 small, 96 for GPT-3 175B, 80 for LLaMA 3 70B.

Every block reads from and writes to the same residual stream. Nothing is overwritten — each block adds its contribution. This is why you can stack eighty of them and still have gradients reach the bottom.

Why residuals

Notice that the input and output of a block have the same shape. The block does not transform its input; it computes a correction and adds it. This is the residual connection, and it is the single most important reason deep transformers are trainable at all.

Without it, gradients have to flow back through every sub-layer's non-linearity, and they vanish long before they reach the embedding. With it, there is a direct additive path from the loss to every layer, and the sub-layers only need to learn a small correction on top of an identity function.

There is a useful way to think about this. The residual stream is a shared communication channel, d_model wide, running the length of the model. Every attention head reads from it and writes its output back into it. Every FFN does the same. Nothing is private; the stream is the only thing that persists. Once you see it this way, a lot of transformer behaviour stops being mysterious.

Why layer norm, and where to put it

Layer norm normalises each token's activation vector to zero mean and unit variance across the feature dimension, then applies a learned scale and shift. It keeps activations in a stable range as they propagate through many layers.

Where it sits matters, and this changed. The original 2017 paper put layer norm after each sub-layer, at the end of the residual path. That arrangement — post-LN — requires a learning-rate warmup and is fragile at depth. Almost every model since 2020 puts it before the sub-layer instead, inside the residual path. This is called pre-LN, and it trains stably without warmup tricks, which is why it became the default.

Most current open models have moved further, to RMSNorm, which drops the mean-centering step and keeps only the root-mean-square scaling. It is cheaper, and empirically just as good. LLaMA, Mistral, and most of what you would download today use it.

Why a feed-forward network

Attention is a linear operation on the values — a weighted average. Averaging is not very expressive on its own. The FFN is what gives the block non-linear processing capacity: it is a two-layer MLP, applied identically to each position, with an expansion in the middle. Typically the hidden dimension is 4× the model dimension.

The original paper used ReLU. Modern models use GELU or, increasingly, SwiGLU — a gated variant that multiplies two projections together and is consistently a small win at the same parameter count.

The FFN is described as "position-wise" because it has no interaction between positions at all. Each token goes through the same MLP independently. All communication between positions happens in attention; all per-position computation happens in the FFN. The two sub-layers have entirely separate jobs.

Part VI · Where the parameters actually live

People assume attention is where the model's knowledge lives. It is not, and the arithmetic is simple enough to do on the back of an envelope.

Attention in one block has four projection matrices — Wq, Wk, Wv, Wo — each of size dmodel × dmodel. That is roughly 4·d2 parameters, ignoring biases.

The FFN has two matrices: dmodel × dff and dff × dmodel. With the standard dff = 4·dmodel, that is 8·d2 parameters.

attention · 33%
feed-forward · 67%
4·d² — W_q, W_k, W_v, W_o 8·d² — up-projection and down-projection

Per block, ignoring biases, embeddings, and the final output head. The ratio holds across GPT-2, GPT-3, and LLaMA-family models.

Two-thirds of the parameters in every block are in the feed-forward network. This is where most of the model's factual capacity is thought to live, and it is why mixture-of-experts architectures — which scale the FFN while keeping attention shared — are the current approach to making models bigger without making inference proportionally more expensive.

The practical implication: if you are trying to understand where a model stores knowledge, attention is the wrong place to look. Attention decides what information to move. The FFN decides what to do with it.

Part VII · The causal mask

The original transformer was an encoder-decoder built for translation: an encoder reads the whole source sentence, a decoder generates the target. The decoder needs a constraint the encoder does not — when predicting token 5, it must not be able to see tokens 6 onwards, because those do not exist yet at inference time.

The fix is a mask. Before softmax, set every score in the upper triangle of the n × n matrix to negative infinity. After softmax those become exactly zero.

mask(M)ij= Mij if j ≤ i,  −∞ otherwise
Causal mask · applied to scores before softmax

Why negative infinity and not zero? Because the mask is applied before softmax. Zero would still let the value through as a real score, and after exponentiation it would be 1 — a meaningful contribution. Negative infinity exponentiates to 0, which is a true zero weight.

Note that the mask makes the model autoregressive only in combination with the position-by-position generation loop. The mask guarantees that position i's representation depends only on positions ≤ i. That means you can compute all positions in parallel during training, because each one is already constrained not to see the future. It also means you can cache the key and value tensors and generate one token at a time without recomputing anything.

This is the deep trick of the architecture. A recurrent network cannot be trained in parallel, because the hidden state genuinely depends on the previous step. A masked transformer can, because the dependency is enforced by the mask rather than by the computation order. You get parallel training and sequential generation from the same model.

The three architectures

That gives you the three families, distinguished entirely by which parts have a causal mask:

  • Encoder-only (BERT). No mask anywhere. Every token sees every other token in both directions. Excellent for classification and embeddings, cannot generate.
  • Decoder-only (GPT, LLaMA, Claude). Mask everywhere. Every token sees only the past. The dominant architecture for generation, and for essentially every current LLM.
  • Encoder-decoder (T5, the original transformer). Unmasked encoder reading the input, masked decoder generating the output and cross-attending to the encoder's output.

Decoder-only won for language modelling, largely because it is simpler and because next-token prediction on raw text turned out to be enough to learn everything the other architectures were learning.

Part VIII · Positional encoding

Attention is order-blind, so order has to be injected somewhere. The original paper added a fixed sinusoidal vector to each embedding — different frequencies for different dimensions, so that relative positions have a consistent linear relationship.

Learned positional embeddings (GPT-2) replaced that with a lookup table, one vector per position, trained like any other parameter. Simpler, works well, but does not extend beyond the maximum length seen in training.

Almost everything current uses rotary position embedding (RoPE). Instead of adding a vector, RoPE rotates the query and key vectors by an angle proportional to their position. The consequence is elegant: the dot product between a query at position m and a key at position n depends only on the difference m − n. Relative position is baked into the geometry rather than learned, which is why models trained at 4K context can be extended to 128K with some interpolation rather than retraining.

RoPE is worth understanding properly, and it is the planned subject of the next lesson. For now: it is the mechanism behind almost every "we extended the context window" announcement you have read in the last two years.

Part IX · Training and inference are different problems

This is the part that surprises people who know the architecture but have not deployed it.

Training is parallel. You feed a whole sequence at once, the causal mask keeps each position honest, and one forward pass computes the loss at every position. A 2,000-token document is a single training example with 2,000 prediction targets.

Inference is sequential. You generate one token, append it, and run the model again to generate the next. The naive way to do this recomputes the key and value projections for the entire sequence on every step, even though nothing about the earlier tokens changed.

The KV cache is the fix. Store the key and value tensors from every previous step, and each new token only computes its own projections — then attends against the cached keys and values. This turns generation from quadratic per-token work into linear, and it is why any real deployment has one.

The cost is memory. The cache size is proportional to batch size × sequence length × layers × heads × head dimension × 2. For a large model with a long context, this dominates GPU memory — which is why grouped-query attention exists. GQA lets several query heads share one key/value head, shrinking the cache by the sharing factor at a small quality cost. LLaMA 3, Mistral, and essentially every recent open model use it.

Why this matters for you

Two-thirds of the operational complexity of serving a model comes from this section. If a context window is expensive, it is because the KV cache grows linearly with it. If a long prompt makes throughput collapse, that is the cache filling memory. If an inference provider offers a suspiciously cheap long-context option, they are almost certainly doing something clever with the cache.

Part XI · What attention cannot do

Every mechanism has a shape, and knowing the shape tells you where it breaks. Four limitations matter in practice.

It is quadratic

Nothing in the architecture avoids the n2 score matrix. At 8K tokens that is 64 million scores per head; at 128K it is 16 billion. FlashAttention makes this tractable by never materialising the full matrix in memory, computing it in tiles instead — but the arithmetic is unchanged. It is faster, not cheaper asymptotically.

Every genuinely sub-quadratic approach — sliding window, sparse, linear attention — trades exactness for scale. Whether that trade is worth it depends on the task, and the field is not settled.

It has no notion of order

Positional encoding is a patch, not a solution. It works, but it means the model's sense of position is a learned or injected approximation layered on top of an operation that is fundamentally indifferent to sequence. This is why context extension is fiddly, and why models degrade in characteristic ways beyond their training length.

It is not a computer

A single attention layer performs one weighted average. It cannot do arithmetic, follow a chain of reasoning, or compose two operations. Any apparent computation comes from stacking many layers, with the FFN providing the non-linearity and the residual stream accumulating intermediate state. Depth is doing the work, not attention.

This is the strongest argument for why chain-of-thought prompting works at all: it lets the model use its own generated tokens as scratch space, effectively adding computation steps that a single forward pass cannot provide.

Its weights are not its reasoning

Covered above, but worth repeating because it is so often forgotten. Attention weights tell you where information was routed, not what the model concluded or why. Heads are redundant, and ablating one frequently changes nothing.

Part XIII · Check yourself

Answer from memory before scrolling back. The effort of retrieval is what makes this stick; rereading would feel smoother and teach you less.

Question 01

Why is the dot product divided by the square root of the key dimension before softmax?

To stop the softmax from saturating. Dot products grow with dimension — variance scales with dk — and softmax on large-magnitude inputs becomes nearly one-hot, concentrating all weight on a single token and killing gradients everywhere else. Dividing by √dk restores unit variance. It does nothing for the quadratic cost and nothing for output magnitudes.
Question 02

Roughly what share of parameters in a transformer block live in the feed-forward network rather than attention?

About two thirds. Attention has four d² matrices (≈4d²); the FFN has two with a 4× expansion (≈8d²). So the split is 33 / 67. This matters because attention is where people look for "knowledge" — but the FFN is where most of the capacity actually is, and it is why mixture-of-experts scales the FFN and shares attention.
Question 03

Why is the causal mask set to negative infinity rather than zero before softmax?

Zero would survive softmax as a real weight. The mask is applied to raw scores, before softmax. A score of 0 exponentiates to 1 — a fully meaningful contribution, so the model would still see the future. Negative infinity exponentiates to exactly 0, which is a true zero. The mask has to be applied before softmax for this reason, not after.
Question 04

What does the KV cache actually eliminate during token-by-token generation?

The need to reproject previous tokens. Without a cache, each generation step recomputes K and V for the whole sequence — even though earlier tokens have not changed. The cache stores them so each new token only projects itself. Attention still runs, the mask still applies, the FFN still runs. It is purely a redundancy elimination, which is why it is exact rather than approximate. Its cost is memory, which is why GQA exists.
Question 05

What distinguishes a decoder-only model from an encoder-only model?

The decoder applies a causal mask always. Architecturally the two families are nearly identical — same block, same attention, same FFN. The only structural difference is where the mask is applied. A decoder-only model masks everywhere so it can generate; an encoder-only model masks nowhere so it can see both directions. Everything else is a consequence of that one decision.
Question 06

Why does pre-LN placement matter for training deep transformers?

It keeps the residual path free of normalisation. In post-LN, layer norm sits at the end of the residual branch — so gradients flowing back through the skip connection still pass through a normalisation each block, which compounds badly at depth and requires careful warmup. Pre-LN moves the norm inside the branch, before the sub-layer, leaving the skip connection a clean additive path from output to input. That is what makes 80-layer stacks stable. The remaining options all describe things pre-LN does not do.
