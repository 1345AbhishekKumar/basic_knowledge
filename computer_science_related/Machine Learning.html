Machine Learning in One Hour

Every method on the scikit-learn cheat sheet is the same three steps: a model, a loss, an optimizer. Make a guess, score how wrong it is, improve the guess. We'll build that intuition on one tiny toy example — Sam's iced coffee cart.

Lesson 0 · The foundation

The whole of machine learning is one recipe

You are not bad at this. You were taught in the wrong order. Every method in this hour — linear regression, logistic regression, K-means, PCA — is the same three boxes filled in differently.

Definitions · what machine learning actually is

Machine learning the field
Building a formula from data instead of writing the rules by hand. You show the computer past examples; it tunes the formula; then it predicts on new examples. Classical programming: you write the rules. Machine learning: you supply examples and the rules are fitted.
Model box 1
The formula whose numbers you are allowed to change. In this course the model is always something simple — a straight line, a squashed line, a set of landmarks, a set of directions. Sam's version: "cups = W × temp + B."
Parameter the dials
A number inside the model that the optimizer is allowed to change. Linear regression has two: the slope W and the intercept B. Parameters are what "learning" actually means — you are searching for good numbers, not writing new code.
Feature input
An input column you feed the model. Sam's features are temperature, people per hour, and litres of milk bought. Also called an input, predictor, or independent variable.
Label / target answer
The answer column you want the model to reproduce. For linear regression it is cups sold. For logistic regression it is the yes/no "needed a second crate". Also called the output or dependent variable.
Loss box 2
One single number that scores how wrong the model is. Lower is better. It is also called the cost function, objective, or error. It has to be one number, because you cannot search for the best model if "better" is not measurable. Sam's versions: MSE for cups, log loss for yes/no.
Optimizer box 3
The procedure that searches for the parameter values that make the loss as small as possible. Some optimizers are exact formulas (linear regression), some are iterative walks (gradient descent), some are greedy loops (K-means), some are matrix routines (PCA).
Training / fitting the verb
Running the optimizer on your data to find good parameters. "Fitting a line" and "training a model" mean the same thing.
Prediction the output
What the fitted model outputs for a given input. Written ŷ ("y-hat") in most textbooks. Sam's version: "the line says 30 cups on a 12 °C day."
Supervised learning has answers
Learning where every training row already carries the correct answer. You can measure the error directly. Linear regression and logistic regression live here.
Unsupervised learning no answers
Learning where there is no answer column at all — you only have the inputs, and you look for structure in them. There is no "correct" to compare against, so the loss has to measure something else (like distance, or lost spread). K-means and PCA live here.
Regression job type
Predicting a number. How many cups tomorrow? What price? What temperature?
Classification job type
Predicting a category. Yes or no. Cat or dog. Spam or not spam. With two categories it is called binary classification.
Overfitting the classic failure
When a model fits the training days so closely that it has memorised their noise instead of learning the pattern, and then does badly on new days. The fix is usually to keep the model simple, or to test it on days it has never seen.
Generalisation the goal
How well a model does on new data it was not trained on. This is the only thing that actually matters. A model that scores 0.00 on the days it saw but fails on tomorrow is useless.

Meet Sam

Sam runs a small iced coffee cart on the market square. Every night he faces the same decision: how much milk do I buy for tomorrow?

Buy too much and money goes down the drain with the spoiled milk. Buy too little and the milk runs out with customers still in line.

Milk comes in crates of 12 litres. A cup takes a quarter of a litre — so one crate = 48 cups.

Lesson 1 · Regression

How many cups will Sam sell tomorrow?

Turn a temperature into a cup count. We'll plot six clean days, fit one straight line through them, and find out how far off that line is.

Definitions · linear regression

Linear regression the method
A model that predicts a number as a straight-line function of its input. "Linear" means the output changes by a fixed amount for every one-unit change in the input — no curves, no bends, no thresholds. It is the simplest predictive model there is, and the one every other method gets compared against.
Slope (W) parameter
How much the prediction changes when the input goes up by one. In Sam's line, W = 3 means every extra degree is worth about three more cups. A slope is a rate. If W were negative, warmer days would mean fewer sales.
Intercept (B) parameter
Where the line sits when the input is zero. In Sam's line, B = −11 means the formula predicts −11 cups at 0 °C. That is physically nonsense — but it is just an arithmetic anchor that shifts the line up or down to fit the days Sam actually has. The intercept does not have to be meaningful on its own.
Straight line equation the model
ŷ = W × x + B. Two parameters, one input. Everything else in this lesson is about choosing the best W and B.
Error / residual one day's miss
The gap between what the line said and what actually happened: error = prediction − actual. A positive error means the line guessed too high; a negative error means it guessed too low. One error per day, one number per error.
Squared error the fix
Just the error multiplied by itself: error². Squaring does two things. First, it makes every error positive, so misses above and below the line can no longer cancel each other out. Second, it makes big misses count disproportionately more than small ones. A 6-cup miss costs 36; three 2-cup misses cost 12 between them.
Mean squared error (MSE) the loss
The average of all the squared errors: MSE = (1/n) × Σ(prediction − actual)². Six errors go in, one number comes out. That is what makes it usable as a loss — you can compare any two candidate lines by comparing their MSE, and lower always wins. Sam's best line scores 0.67; both of his bad guesses score 12.33.
Least squares the principle
The idea of choosing the parameters that make the sum (or mean) of the squared errors as small as possible. Linear regression fitted with MSE is least-squares fitting.
Fitting the verb
Searching for the W and B that minimise the loss. In this lesson we do it by drawing the bowl and reading the bottom off it.
Loss curve / the bowl why it's easy
If you plot the loss for every possible value of one parameter, you get a U-shape. A U-shape has exactly one lowest point, so there is no danger of getting stuck somewhere wrong. This is a special, lucky property of linear regression with MSE — logistic regression and neural networks do not have it.
Convex the property
Mathematical name for "bowl-shaped" — a curve where any straight line between two points on it lies above the curve. A convex loss has one global minimum and no traps. MSE as a function of W and B is convex.
Normal equation / closed form the shortcut
An exact algebraic formula that jumps straight to the best parameters in one calculation, without searching: β = (XᵀX)⁻¹XᵀY. It works for any number of input columns. You do not need to understand it — just know that for linear regression the answer can be computed directly.
Design matrix (X) the setup
Your data arranged as one block: one row per example, one column per feature. A column of all ones is added at the front so that the intercept B has something to multiply. Sam's X has 6 rows and 2 columns: a column of ones, and the temperatures.
Extrapolation the danger
Using the fitted line on inputs far outside the range you trained on. Sam's line was fitted on 12–22 °C. At 40 °C it will happily predict 109 cups, because a straight line never stops climbing — but the real world bends. This is exactly the trap the PCA lesson exposes.

Pop quiz

A 6-cup error squares to 36. Three separate 2-cup errors square to 4 each — 4 + 4 + 4 = 12. What does that tell you about squaring?

Answer: B. One 6-cup error costs 36, while three 2-cup errors cost 12 between them — even though both add up to six cups of error. Squaring decides that being badly wrong once is worse than being slightly wrong often. That's a choice we are making, not a fact about the data. (A is wrong because squaring treats errors very unevenly. C is wrong because simple adding would be easier. D is wrong because 1.5 squares to 2.25 just fine.)

Step 4 — Find the bottom of the bowl

So B = 40 − 17 × W. Now only W is left to choose, and the loss becomes a U-shaped curve in W.

The bowl has exactly one lowest point, so it's easy to find. Move the W slider above and watch the marker slide along this curve.

The bottom sits exactly at W = 3, where the loss is 0.67. Then B = 40 − 17 × 3 = −11.

So Sam's line is cups = 3 × temp − 11. Its six errors are −1, +1, +1, −1, 0, 0 — every day off by at most one cup.

Lesson 2 · Classification

Does Sam need a second crate?

This question needs a yes or a no. We'll keep the straight line from before, squash its output into a number between 0 and 1 with an S-shaped curve, and fit it against yes/no answers.

Definitions · logistic regression & gradient descent

Classification job type
Predicting a category rather than a number. When there are exactly two categories — yes/no, true/false, crate/no crate — it is called binary classification. The output is usually expressed as a probability, and a threshold turns that probability into a decision.
Probability the output
A number between 0 and 1 that says how sure the model is. 0.826 means "82.6 % confident". A count can never express certainty, which is exactly why a cup-count model cannot answer a yes/no question.
Odds related idea
The ratio p / (1 − p). A probability of 0.5 is odds of 1 ("even money"). Logistic regression is literally linear in the log-odds — that is where the name comes from.
Logit / score before the squash
The raw straight-line output W × x + B before the sigmoid is applied. It can be any number at all: negative, zero, huge. Day 8's score was 1.560. The logit is where the straight line lives; the sigmoid just converts it.
Sigmoid / logistic function the squasher
A fixed S-shaped curve, σ(z) = 1 / (1 + e^(−z)), where e ≈ 2.72. It takes any number, however large or small, and returns a value strictly between 0 and 1. At z = 0 it returns exactly 0.5. It flattens out at both ends, so it never predicts a 126 % chance or a −2 % chance. It has no parameters of its own — it is a fixed shape you bolt onto the end of the line.
Logistic regression the method
Linear regression plus a sigmoid. The name is confusing: despite saying "regression", it is a classification method — the name is historical. Model: a straight line squashed into a probability. Loss: log loss. Optimizer: gradient descent.
Decision threshold / decision boundary the rule
The cut-off that turns a probability into a category. The default is 0.5 — above means yes, below means no. The model itself never decides; it only reports a probability. Sam (or you) chooses the threshold, and moving it trades one kind of error for the other: a lower threshold means more crates bought and less milk run out, but more sour milk poured away.
Log loss / binary cross-entropy the loss
−log(probability the model gave to the answer that actually happened). Every day pays a fee based on how much probability it assigned to the truth. If the model said 0.99 for something that turned out true, the fee is small (−log 0.99 ≈ 0.01). If it said 0.99 for something that turned out false, the fee is enormous (−log 0.01 ≈ 4.61). It has no upper limit — which is exactly what you want for a model that is confident and wrong.
Why not just square the error here? the reasoning
Because a probability is capped at 1, a squared error can never exceed 1. So "completely sure and wrong" (0.99 → 0.98) costs almost the same as "mostly sure" (0.83 → 0.68). Squaring runs out of room precisely where the mistake matters most. Log loss does not.
Gradient descent the optimizer
An iterative method that walks downhill on the loss surface one small step at a time. Picture standing on a hill in thick fog: you cannot see the bottom, but your feet can feel which way is down. Take a step that way, feel again, repeat. It never knows the answer in advance — it only follows the slope.
Gradient the slope
The multi-dimensional slope of the loss — the direction of steepest ascent. To go downhill you step against it. For logistic regression the gradient with respect to the parameters works out beautifully to prediction − truth, which is why the update is so clean.
Learning rate the step size
The one number you choose in gradient descent. It multiplies the gradient to decide how far you move each step. Too small: you crawl toward the bottom in tiny steps and it takes forever. Too big: you leap clean over the minimum and land higher up on the far side — or bounce forever and never settle. A typical starting value is 0.01 to 0.1.
Convergence when to stop
When the loss stops meaningfully improving — the steps become so tiny that further iterations change nothing. The curve flattens out near the bottom of the bowl.
Epoch / iteration the loop
One full pass through the training data. Gradient descent repeats this many times, each time nudging the parameters a little closer to the bottom.
Accuracy the score
The fraction of days the model classified correctly after the threshold is applied. Sam's model got 7 out of 9. Note that accuracy ignores how confident the model was — that is what the log loss measures.
Logistic vs linear — what changed summary
Step 1 (model) changed: the line got squashed. Step 2 (loss) changed: MSE became log loss. Step 3 (optimizer) changed: the exact formula became gradient descent. Same three boxes, different contents.

Milk only comes in whole crates, so Sam can't buy one and a half. He either takes a second crate or he doesn't. A count and a yes/no are two different questions, and they need two different models.

Building the answer column

One crate serves 48 cups. So any day Sam sold more than 48 cups was a day he needed a second crate.

Days 5, 6, 7 and 9 say yes. Every other day says no.

Why not just guess? A wrong yes leaves milk to sour in the crate. A wrong no turns customers away. Sam wants a probability — a number between 0 and 1 that says how sure the model is.

And the model only ever gives back that number. So Sam still needs a rule to act on. He draws a line at 50 percent, right in the middle.

Two new words. When the answer you want is a number, like how many cups Sam will sell tomorrow, that job is called regression. When the answer is a category instead, like a second crate or no second crate, that job is called classification.

Why a straight line fails

Turn yes and no into numbers — no = 0, yes = 1 — then fit the same straight line to those zeros and ones. On a hot day it says 1.261, a 126 percent chance. On a cold day it says −0.022, a minus 2 percent chance. A straight line does not know that a probability has to stop at zero and at one.

We need a curve that flattens out at both ends. That S-shaped curve is called the sigmoid, and it turns any score into a probability between 0 and 1.

Lesson 3 · Unsupervised learning

What kinds of day is Sam actually having?

Sam has two models now, and both of them predict. Tonight he wants to understand his sales instead.

Definitions · clustering and K-means

Unsupervised learning the family
Learning from data that has no answer column. There is nothing to predict correctly, so the goal changes from "get the right answer" to "find useful structure". The two jobs in this half of the map are clustering (find groups) and dimensionality reduction (find fewer columns).
Clustering the job
Grouping rows so that rows inside a group are more similar to each other than to rows in other groups. Nobody tells the algorithm which rows belong together — it works purely from closeness. The groups it produces are called clusters.
K-means the method
The most common clustering algorithm. You choose K, the number of groups. It places K landmarks, assigns every row to its nearest landmark, moves each landmark to the centre of its rows, and repeats until nothing changes. Model: K landmarks. Loss: total squared distance. Optimizer: the greedy assign–move loop.
K the setting
The number of clusters you ask for. K is not learned from the data — you must choose it. K-means will happily split a single blob into K pieces if you ask it to, so the choice matters. The elbow method is one way to pick it.
Centroid the landmark
The centre of a cluster — technically the arithmetic mean of all the points in it. In this lesson it is drawn as a coloured ✕. A centroid is not usually one of Sam's actual days; it is a new point that sits in the middle of a group. "Centroid" and "landmark" mean the same thing here.
Distance / Euclidean distance the measure
How far apart two points are in a straight line, computed with Pythagoras: √((x₁−x₂)² + (y₁−y₂)²). It is the ordinary "as the crow flies" distance, extended to as many columns as you like.
Squared distance what's actually used
The same sum without the square root: (x₁−x₂)² + (y₁−y₂)². K-means keeps the squared version because it behaves identically for ranking (the nearest point is the nearest either way) but avoids computing square roots. The landmark at (16, 52) is 25 squared-units from day 5 at (20, 49): 4² + 3² = 25.
Inertia / within-cluster sum of squares the loss
The total of all the squared distances from every day to its own landmark. Lower is better. Sam's three groups score 522.0. It is also sometimes called the "distortion".
Assign step half the loop
Give every day to the landmark it is nearest to, using squared distance. One pass through the data, one decision per row. Also called the "expectation" or "assignment" step.
Update / move step the other half
Move every landmark to the average centre of the days that just joined it. If a landmark received no days at all, it stays where it is. Also called the "maximisation" step.
Lloyd's algorithm the proper name
The formal name for "assign, move, repeat" — the standard K-means loop. Each half improves the loss, so the loop can never get worse, which is why it always terminates.
Convergence when to stop
When a full assign pass changes nothing — no day switches groups. At that point the landmarks are stable and further passes would do nothing. Sam's run converged in three rounds.
Greedy algorithm the limitation
A method that always makes the locally best move without looking ahead or reconsidering earlier choices. K-means is greedy: it never retries a different starting point, and it never re-opens a settled decision. A consequence is that different random starts can give different final groups, and none of them is guaranteed to be the best possible.
Local optimum the trap
A solution that no small change can improve, but which is not the best solution overall. K-means can settle into one depending on where it started.
Random restarts / k-means++ the fix
Running the whole algorithm several times from different random starting days and keeping the run with the lowest final loss. k-means++ is a smarter seeding method that spreads the starting landmarks out. Real tools do this by default.
Elbow method choosing K
Plot the total squared distance for K = 1, 2, 3, 4, … Every extra group lowers the score, so the score alone never says stop. Instead look at how much each extra group helps — the curve bends sharply and then flattens. The bend (the "elbow") is a reasonable K. Sam's bends at 3. It is a heuristic, not a proof: sometimes the bend is ambiguous, or your domain knowledge points somewhere else.
Feature scaling a real-world caveat
Because K-means literally adds up distances across columns, a column measured in large numbers (like people per hour, ranging 30–68) will dominate a column measured in small numbers (like temperature, ranging 12–34). In practice you standardise the columns first. In Sam's toy example the ranges happen to be similar, so we skip it.
Correlation is not causation the warning
K-means can show you that hot days and low sales cluster together. It cannot tell you why. The pattern is a description of the data, not an explanation of it.

Look at what this question is missing. Every question so far had its answer sitting in a column Sam could point at. This one has no column. There is no answer to learn from and nobody to ask.

Sam answers "do you have the answers?" with a no — and that opens the half of the map we've never been on: unsupervised learning.

Finding groups is called clustering. The other job on this side is building a few new columns to replace many old ones — dimensionality reduction (that's PCA, next lesson).

The trap and the way out

To sort the days, "similar" has to mean something we can measure. We measure how far apart two days are using two of Sam's columns: temperature and cups. Each group gets a landmark — a single point that marks its centre, which textbooks call the centroid.

Every day joins its nearest landmark. That one check is the whole assigning rule.

The trap: to place the landmarks, we need the groups. And to find the groups, we need the landmarks.

The way out: a guess that is almost certainly wrong — made on purpose. Pick K days at random and drop your starting landmarks right on them.

Measuring "near"

A landmark sits at 16 °C and 52 cups. Day 5 is at 20 °C and 49 cups. That's 4 degrees across and 3 cups down. Pythagoras gives 4² + 3² = 25, so the straight line is 5 units long.

K-means keeps the 25 and skips the square root. That 25 is the squared distance.

Notice the units: we're adding degrees to cups as if they were the same kind of number. That works here because temperature and cups move over similar ranges.

Lesson 4 · Dimensionality reduction

Four columns will not fit on one chart

PCA works with all four columns at once — and it will let us check the pattern K-means just found.

Definitions · PCA and the statistics behind it

Dimensionality reduction the job
Replacing many columns with fewer new columns, while keeping as much of the original information as possible. It is useful for three reasons: you can plot the result, the data takes less storage and less compute, and noise gets squeezed out along with the least important directions. A "dimension" here just means a column.
Projection the mechanism
Flattening data onto a line, a plane, or a lower-dimensional space — like shining a lamp on a solid object and looking at the shadow on the wall. Every point drops straight down onto the chosen direction. The direction you choose determines how much of the shape you can still see.
Principal component analysis (PCA) the method
The method that finds the best directions to project onto. "Best" means: the directions along which the data is most spread out. Model: a set of directions. Loss: the spread that gets lost when you flatten. Optimizer: an exact matrix routine (eigen decomposition) that finds every direction at once. PCA is unsupervised — it never looks at an answer column.
Mean / average the centre
The sum of the values divided by how many there are. Sam's average temperature is 23 °C; his average is 39.3 cups a day. Almost every statistic here is measured relative to the mean.
Variance the spread
A number for how spread out a column is: take each value's distance from the average, square each distance, and average the squares. variance = (1/n) × Σ(x − mean)². Note it is built from exactly the same squaring trick as MSE. Variance is the quantity PCA is trying to preserve. Sam's cups have variance 130.9. Low variance = everybody agrees; high variance = the column actually carries information.
Standard deviation spread in real units
The square root of the variance, which brings the number back into the original units so you can talk about it. Cups: variance 130.9 → standard deviation ≈ 11 cups. So a typical day is about 11 cups away from the average.
Standardisation / z-score levelling the columns
Rewriting every value as "how many standard deviations from the average": z = (x − mean) / std. After standardising, every column has mean 0 and variance 1, so no column can shout louder than another simply because it is measured in bigger numbers. Day 7 had 68 people per hour; the average is 46.8 and the standard deviation is 13.6, so day 7 lands at 1.56 steps. PCA is almost always run on standardised data.
Covariance do two columns move together?
A number for whether two columns rise and fall together. It is the average of the products of their standardised values. Positive means they move in the same direction; negative means they move in opposite directions; near zero means no linear relationship.
Correlation covariance, scaled
Covariance divided by both standard deviations, which forces the answer into the range −1 to +1 and makes it comparable across pairs. +1 is a perfect straight-line upward relationship, −1 is perfect downward, 0 is none. People and cups: 0.96 — almost perfectly in step.
Covariance matrix the input to PCA
A square grid holding the covariance (or correlation) between every pair of columns. For four columns it is 4×4. The diagonal holds each column's variance with itself; the rest holds the pairwise relationships. PCA takes this table as its input.
Multicollinearity why it matters
When two input columns carry almost the same information — like people and cups, correlated 0.96. You could drop one and lose almost nothing. PCA generalises that idea: it finds the combinations of columns that are redundant and merges them.
Direction / component a new column
A blend of the old columns, described by a set of weights — one weight per original column. Following that direction a certain distance gives you a new value for each day. The new columns are called principal components: PC1, PC2, and so on, ordered by how much spread they capture.
Eigen decomposition the routine
The matrix operation that takes the covariance table and returns every direction ranked by spread. It is an exact, single-shot calculation — no searching, no iterating. You do not need to be able to do it by hand; you only need to know what it produces.
Eigenvector a direction
One direction, written as its weights on the original columns. Direction 1 has all positive weights; direction 2 has heat and milk up while people and cups go down. The eigenvector tells you where to look; the eigenvalue tells you how much is there.
Eigenvalue that direction's spread
The amount of variance captured along its eigenvector. Bigger eigenvalue = more information preserved if you keep that direction. Ranking the eigenvalues ranks the directions by usefulness.
Explained variance ratio how much did we keep?
Each direction's eigenvalue divided by the total of all eigenvalues — the fraction of the total spread that direction accounts for. Sam's first two directions keep 95.3 %, so the other two can go. This is the number you use to decide how many components to keep.
Orthogonal non-overlapping
Perpendicular. The principal components PCA produces are all at right angles to each other, which guarantees the new columns carry no overlapping information — unlike the original columns, which did.
Loadings how to read a component
The weights of the original columns inside a component. Reading them tells you what the component means. Sam's PC1 loads positively on everything, so it reads as "how busy the day was". PC2 has heat and milk going one way and people and cups the other, so it reads as "how hot it was".
Curse of dimensionality why fewer is better
The informal observation that as you add columns, data becomes sparse, distances become less meaningful, and models need far more examples to learn from. Reducing dimensions can make everything else work better.
The trade-off the honest caveat
PCA compresses, so something is always lost — Sam gave up 4.7 % of the spread. And the new components are blends, which are harder to explain to another human than "temperature" or "cups sold". You gain simplicity and lose interpretability.

The key idea: machine learning is one recipe.

One — Model. Pick a formula with numbers we are allowed to change.
Two — Loss. Measure its errors with one number.
Three — Optimize. Find the values that make that error smaller.

The core recipe
Machine learning the field Building a formula from data instead of writing the rules by hand. You supply past examples; the computer tunes the formula; then it predicts on new examples.
Model box 1 The formula whose numbers you are allowed to change — a straight line, a squashed line, a set of landmarks, a set of directions.
Parameter the dials A number inside the model that the optimizer is allowed to change. Learning = searching for good parameter values. Linear regression has two: slope W and intercept B.
Feature input An input column fed to the model. Sam's are temperature, people per hour, and litres bought. Also called input, predictor, or independent variable.
Label / target answer The answer column the model tries to reproduce. Cups sold for regression; yes/no for classification. Also called output or dependent variable.
Loss box 2 One number scoring how wrong the model is. Lower is better. Also called cost function, objective, or error. It must be a single number, or "better" is not measurable.
Optimizer box 3 The procedure that searches for the parameter values which make the loss smallest. Can be an exact formula, an iterative walk, a greedy loop, or a matrix routine.
Training / fitting the verb Running the optimizer on your data to find good parameters. "Fitting a line" and "training a model" mean the same thing.
Prediction the output What the fitted model outputs for a given input, written ŷ. "The line says 30 cups on a 12 °C day."
Supervised learning has answers Learning where every training row already carries the correct answer, so error can be measured directly. Linear and logistic regression live here.
Unsupervised learning no answers Learning with no answer column at all — only inputs, and the goal is to find structure. K-means and PCA live here.
Regression job type Predicting a number: how many cups, what price, what temperature.
Classification job type Predicting a category: yes/no, cat/dog, spam/not spam. Two categories = binary classification.
Overfitting the classic failure Fitting the training days so closely that you memorise their noise instead of the pattern, then doing badly on new days.
Generalisation the goal How well the model does on data it has never seen. The only thing that actually matters.
Linear regression
Linear regression the method Predicting a number as a straight-line function of the input. "Linear" means a fixed change in output per unit change in input — no curves, no bends.
Slope (W) parameter How much the prediction changes when the input rises by one. W = 3 means every extra degree is worth about three more cups. A slope is a rate.
Intercept (B) parameter Where the line sits when the input is zero. B = −11 in Sam's line. It need not be physically meaningful — it is just the arithmetic anchor that shifts the line up or down.
Straight-line equation the model ŷ = W × x + B. Two parameters, one input.
Error / residual one day's miss The gap between prediction and reality: prediction − actual. Positive = guessed too high; negative = guessed too low.
Squared error the fix error². Makes every error positive so misses cannot cancel out, and makes big misses count disproportionately more: one 6-cup miss costs 36, three 2-cup misses cost 12.
Mean squared error (MSE) the loss The average of all squared errors. Six errors in, one number out. Sam's best line scores 0.67; his two bad guesses score 12.33.
Least squares the principle Choosing parameters that make the sum of squared errors as small as possible. Linear regression with MSE is least-squares fitting.
Loss curve / the bowl why it's easy Plotting loss against one parameter gives a U-shape with exactly one lowest point, so there is no danger of getting stuck somewhere wrong.
Convex the property Mathematical name for bowl-shaped: a curve where the straight line between any two points lies above the curve. Convex losses have one global minimum and no traps.
Normal equation / closed form the shortcut An exact formula giving the best parameters in one calculation: β = (XᵀX)⁻¹XᵀY. Works for any number of input columns.
Design matrix (X) the setup Data arranged as one block: one row per example, one column per feature, plus a leading column of ones so the intercept has something to multiply.
Extrapolation the danger Using the fitted line far outside the range you trained on. Sam's line was fitted on 12–22 °C; at 40 °C it predicts 109 cups, but the real world bends.
Logistic regression & gradient descent
Probability the output A number between 0 and 1 saying how sure the model is. 0.826 means 82.6 % confident. A count can never express certainty.
Odds related idea The ratio p / (1 − p). Logistic regression is linear in the log-odds — that is where the name comes from.
Logit / score before the squash The raw straight-line output W × x + B before the sigmoid is applied. It can be any number at all. Day 8's score was 1.560.
Sigmoid / logistic function the squasher σ(z) = 1 / (1 + e^(−z)). Takes any number and returns something strictly between 0 and 1. At z = 0 it returns exactly 0.5. It has no parameters of its own.
Logistic regression the method Linear regression plus a sigmoid. Despite the name it is a classification method — the name is historical. Model: line + sigmoid. Loss: log loss. Optimizer: gradient descent.
Decision threshold the rule The cut-off that turns a probability into a category, usually 0.5. The model never decides — it only reports a probability. Moving the threshold trades one kind of error for the other.
Log loss / binary cross-entropy the loss −log(probability given to what actually happened). Wrong and confident is punished enormously: −log 0.01 ≈ 4.61. It has no upper limit, which is exactly what is wanted.
Why not square here? the reasoning Because a probability is capped at 1, squared error can never exceed 1 — so "certain and wrong" costs barely more than "mostly sure". Squaring runs out of room exactly where it matters most.
Gradient descent the optimizer Walking downhill on the loss surface one small step at a time. You cannot see the bottom, but your feet feel the slope. Step against it, feel again, repeat. Never knows the answer in advance.
Gradient the slope The multi-dimensional slope of the loss — the direction of steepest ascent. Step against it to go down. For logistic regression it works out to prediction − truth.
Learning rate the step size The one number you choose in gradient descent. Too small and you crawl; too big and you leap past the minimum and land higher up. Typical starting range: 0.01 to 0.1.
Convergence when to stop When the loss stops meaningfully improving and the steps become tiny — the curve has flattened near the bottom.
Epoch / iteration the loop One full pass through the training data. Gradient descent repeats it many times, nudging parameters closer to the bottom each time.
Accuracy the score The fraction of days classified correctly after the threshold is applied. Sam's model got 7 of 9. Accuracy ignores how confident the model was — log loss measures that.
K-means & clustering
Clustering the job Grouping rows so rows inside a group are more similar to each other than to rows outside it. No labels are used — only closeness.
K-means the method Choose K. Place K landmarks. Assign every row to the nearest one. Move each landmark to the centre of its rows. Repeat until nothing changes.
K the setting The number of clusters you ask for. Not learned from the data — you must choose it. K-means will happily split one blob into K pieces if asked.
Centroid the landmark The centre of a cluster — the mean of its points. Usually not one of the actual days; it is a new point sitting in the middle. Same thing as "landmark".
Euclidean distance the measure Straight-line distance via Pythagoras: √((x₁−x₂)² + (y₁−y₂)²), extendable to any number of columns.
Squared distance what's actually used The same sum without the square root. Rankings are identical, so K-means skips the root. The landmark at (16, 52) is 4² + 3² = 25 from day 5.
Inertia / within-cluster sum of squares the loss The total squared distance from every day to its own landmark. Lower is better. Sam's three groups score 522.0.
Assign step half the loop Give every day to the landmark it is nearest to, using squared distance. One pass, one decision per row.
Update / move step the other half Move every landmark to the average centre of the days that just joined it.
Lloyd's algorithm the proper name The formal name for "assign, move, repeat". Each half improves the loss, so the loop can never get worse — which is why it always terminates.
Convergence when to stop When a full assign pass changes nothing — no day switches groups. Sam's run converged in three rounds.
Greedy algorithm the limitation Always makes the locally best move without looking ahead or reconsidering earlier choices. Different random starts can therefore give different final groups.
Local optimum the trap A solution no small change can improve, but which is not the best solution overall. K-means can settle into one depending on its start.
Random restarts / k-means++ the fix Running the algorithm several times from different random starts and keeping the lowest-loss run. k-means++ is a smarter seeding method that spreads the starts out.
Elbow method choosing K Plot total squared distance against K. Every extra group lowers the score, so look at how much each one helps: the curve bends sharply then flattens. The bend is a reasonable K. Sam's bends at 3. A heuristic, not a proof.
Feature scaling real-world caveat Because K-means adds distances across columns, a wide-range column dominates a narrow-range one. In practice standardise first.
Correlation ≠ causation the warning K-means can show that hot days and low sales cluster together. It cannot tell you why.
