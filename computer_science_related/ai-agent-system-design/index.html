1. An LLM is stateless. An agent has state + loop.

An LLM maps tokens in → tokens out and forgets everything. An agent wraps it in a sense–plan–act loop: remember goal, pick a tool, read the result, repeat until done. The loop is the system.

Misconception to kill: “a smarter model removes the need for architecture.” Even GPT-5-class models hallucinate tools, lose context, and loop forever without an orchestrator, memory, and verifier.

4. Why naive agents fail at scale

Three killers: context explosion (every observation eats the window), latency × cost (8 steps × 2k tokens × reasoning model = slow + $), unbounded loops (agent retries forever). Fixes: iteration budget, summarization, caching, parallel tool calls, strict JSON schemas, verifier.

Rule of thumb: context usage > 70% → summarize or retrieve, don’t append. Latency budget → prefer fast model for routing, strong model for planning. Every tool needs timeout + retry + idempotency.

Summary — takeaways

  • Agent = loop + state + tools, not just a prompt. Design the loop first.
  • ReAct (Thought → Action → Observation) is the core protocol; JSON schemas make it reliable.
  • Memory is tiered: working context (hot), vector store (warm), traces/logs (cold). Retrieval beats appending.
  • Production = budgets: max iterations, timeouts, token/cost caps, verifier before side effects.
  • Observe everything: trace each step, track tokens/cost/latency, eval on golden tasks.
