Detailed Architectural Explanations

Retrieval Pattern 01

Exact SQL Time-Series Retrieval

When a query specifies relational filters or strict temporal bounds (e.g. "Show the last 10 messages with customer #441"), executing vector RAG is inefficient and imprecise. The harness utilizes standard SQL index lookups on timestamped relational columns, executing in sub-milliseconds with zero embedding costs.

Retrieval Pattern 02

Hybrid SQL + Semantic Vector RAG

When querying vague concepts across history (e.g. "Find the past 20 conversations where customers complained about shipping delays and our agent failed to resolve it"), the harness runs a hybrid query: first pruning via SQL (status = 'unresolved'), then ranking remaining messages via cosine semantic similarity to extract the 20 exact targets.

-- HYBRID RETRIEVAL BLUEPRINT -- Step 1: SQL Pre-Filter SELECT id, user_id, message_text, embedding FROM customer_turns WHERE status = 'unresolved' AND created_at >= NOW() - INTERVAL '60 days' -- Step 2: Vector Cosine Similarity Ranking (pgvector) ORDER BY embedding <=> embedding('customer complained about shipping delays') LIMIT 20;
