The 3 Context Management Strategies

Lessons from Arize AI building Alex: why Naive Truncation broke reasoning, why LLM Summarization was unreliable, and how Smart Truncation + Memory Store succeeded.

Detailed Architectural Explanations

Core Problem · Context Physics

Why Multi-Turn Sessions Break

Every tool call (SQL query returns, terminal outputs, web scrapes) dumps hundreds of tokens into the context window. Within 5-10 turns, the token limit is approached. How an engineering harness manages this boundary dictates whether the agent successfully finishes the task or suffers amnesia and hallucinations.

Core Breakthrough

Deterministic Truncation vs. Probabilistic Summary

Summarization uses a probabilistic model to summarize a probabilistic model's past thoughts—compounding errors. Smart Head/Tail Truncation replaces probabilistic summarization with deterministic code: keeping the core goal and immediate turns while swapping bulky intermediate logs with retrieval pointers.

1. Core Concept Definitions (Labels in Figure 2.0)

Strategy 1 · Left Column

Strategy 1: Naive Sliding Window (FIFO)

Sliding Window: A standard first-in, first-out (FIFO) queue that retains only the last N messages (e.g. last 8 turns) and discards everything older.
Failure Mode (Amnesia): As turns advance, the queue discards the original System Prompt (identity and tool rules) and the user's root goal. The agent forgets what it was hired to do and begins asking the user who it is talking to.

Strategy 2 · Center Column

Strategy 2: LLM Summarization Compression

Prompt-Based Condensation: Calling an auxiliary LLM every few turns to summarize earlier messages into a narrative paragraph.
Failure Mode (Identifier Dropping): Summaries discard exact IDs (e.g. span_id="0x4a8f9b", database row keys, regex formulas). When the agent needs those exact IDs in Turn 8 to invoke a tool, it hallucinates fake IDs. Recursive summarization also causes hallucination drift.

Strategy 3 · Right Column (Winning)

Strategy 3: Smart Head/Tail Truncation

The "Head": The initial 1-2 turns containing the user's primary prompt and task definition. Never truncated.
The "Tail": The most recent 3-4 turns containing the immediate conversation flow and latest observation. Never truncated.
Middle Offloading: Bulky tool outputs in the middle are saved to a key-value database. The context contains only an ID pointer: [TRUNCATED: ID_104].

Tool Mechanism

On-Demand Context Expansion Tool

fetch_context(chunk_id): A dedicated tool given to the agent. Because the middle messages contain clear ID tags, if the model genuinely needs full historical output from Turn 4, it autonomously calls fetch_context(104) to retrieve that exact block on demand.

2. Step-by-Step Flow: Following the Progression in Figure 2.0

Trace the evolution from left to right as indicated by the arrows connecting the three strategies:

Stage 1 • The Naive Approach Fails (Left Column)

Teams start with naive FIFO message truncation (Strategy 1). At Turn 6, the system prompt and original goal fall out of the sliding window. The model drifts uncontrollably. Arrow 1 points to the attempt to fix this with summarization.

Stage 2 • The Summarization Trap (Center Column)

Teams introduce an LLM summarizer (Strategy 2) to condense old turns. While prose is preserved, the summarizer strips exact database schemas and span IDs. When subsequent tools fail because arguments were lost, teams abandon pure summarization. Arrow 2 points rightward to the production-tested solution.

Stage 3 • Smart Head/Tail + Database Pointers (Right Column)

The winning architectural pattern (Strategy 3): The harness pins the System Prompt and Goal (Head), preserves the last 4 turns (Tail), and replaces middle tool responses with database reference IDs. If the agent needs details, it uses its built-in expansion tool. 100% deterministic, zero hallucinated IDs, minimal tokens.

Production Implementation Blueprint

# SMART TRUNCATION + MEMORY STORE BLUEPRINT def prepare_context(system_prompt: dict, messages: list, max_tokens: int = 8000) -> list: """ Implements Strategy 3: 1. Preserves System Prompt and Goal (Head) 2. Preserves Recency turns (Tail) 3. Offloads verbose middle tool responses to DB with pointer IDs """ head_context = messages[:2] # Initial user prompt & setup tail_context = messages[-4:] # Latest 4 conversational turns middle_messages = messages[2:-4] # Intermediate tool iterations truncated_middle = [] for msg in middle_messages: # If middle tool observation is verbose, save to DB and insert pointer if msg.get("role") == "tool" and len(msg.get("content", "")) > 400: db_id = memory_store.save_payload(msg["content"]) truncated_middle.append({ "role": "tool", "tool_call_id": msg.get("tool_call_id"), "content": f"[TRUNCATED: ID_{db_id}. Use tool 'fetch_context({db_id})' if exact payload is needed]" }) else: truncated_middle.append(msg) return [system_prompt] + head_context + truncated_middle + tail_context
