Detailed Architectural Explanations

Core Tenet 01 · Testing Reality

Why Single-Turn Evals Deceive

90% of AI agent benchmarks test single-turn prompts (e.g., prompt → tool → answer). In production, however, users converse over dozens of turns while navigating complex applications. An agent that scores 98% on Turn 1 can suffer severe memory decay by Turn 8. Long-Session Evaluations explicitly benchmark an agent's reasoning under heavy context load.

Core Tenet 02 · Economics & Latency

The Economics of Prompt Caching

Frontier models (Claude 3.5 Sonnet, Gemini 1.5/2.0 Pro) store the Key-Value (KV) attention tensors of static prompt prefixes in GPU memory. When subsequent calls reuse that identical prefix, providers discount input tokens by up to 80-90% and slash Time-to-First-Token (TTFT) by up to 80%. A stable context layout turns expensive multi-turn sessions into fast, low-cost interactions.

1. Core Component Definitions (Labels in Figure 4.0)

Panel 1 · Left

Long-Session Evaluation Concepts

Synthetic 10-Turn Preload (T1 → T10): A scripted sequence of historical messages and tool calls simulating realistic user interaction, including database queries, errors, and topic switches.
Test Turn 11 Probe: An assertion prompt injected at the end of the 10 preloaded turns (e.g., "What was the span ID diagnosed in Turn 2?") to verify that middle truncation did not accidentally erase crucial historical variables.
Late-Stage Memory Decay: The degradation where an agent begins hallucinating or contradicting its earlier conclusions as context depth increases.

Panel 2 · Right

Prompt Caching Architecture

Static System Prompt (Cached): The immutable prefix containing base agent instructions, role definitions, and tool definitions. Placed at the very top of the context.
Append-Only Turns (Dynamic Tail): New user queries and agent observations appended strictly to the bottom of the prompt.
Cache Invalidation Trap: Inserting dynamic variables (such as Current Time: 14:32:05 or random session tokens) into the system prompt, which completely invalidates the KV-cache on every turn and forfeits discounts.

2. Step-by-Step Flow: How Evals & Caching Operate

Follow the two distinct systems depicted in Figure 4.0:

Flow 1 • Executing the Turn-11 Evaluation Harness (Left Panel)

The evaluation script loads synthetic turns T1 through T10 into the agent's context pipeline. Intermediate tool responses are processed through Smart Truncation. Arrow 1 transitions into Test Turn 11, injecting a targeted verification question. The test asserts that the model's output contains the exact historical ID from Turn 2, confirming that context compaction preserved critical state.

Flow 2 • Maintaining Prefix Stability for Prompt Caching (Right Panel)

The harness structures every API call with strict prefix ordering: (1) Fixed System Instructions → (2) Tool Schemas → (3) Pinned Goal (Head). The model provider caches this block once. As new messages arrive, they are appended to the Dynamic Tail. When middle messages are truncated, they use fixed-length placeholder strings. The provider reuses the cached KV-tensors, yielding ~90% cost savings.
