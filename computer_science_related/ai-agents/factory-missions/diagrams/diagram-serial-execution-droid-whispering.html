Execution Strategy

Why Serial Writes Beat Parallel Chaos

Naively spinning up 10 parallel coding agents causes them to edit overlapping files, generate conflicting database migrations, and waste thousands of tokens on merge resolutions. Missions executes features serially (one write worker at a time), while heavily parallelizing read-only operations (codebase grep, API research, and peer code reviews).

Droid Whispering

Multi-Provider Model Diversity

No single model family is superior across planning, coding, and validation. In Factory Missions, the Validator uses a different model provider than the Implementation Worker (e.g. Gemini validating Claude's code). This ensures the validator does not inherit the same training distribution blind spots as the worker.
