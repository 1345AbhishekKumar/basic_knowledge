Factory Missions: Long-Horizon Multi-Agent Systems

Field-tested insights from Luke (Creator of Goose, Lead Agent Harness at Factory): solving the human attention bottleneck in software engineering through multi-day autonomous agent ecosystems.

1. The New Bottleneck: Human Attention

The fundamental bottleneck in modern software engineering is no longer raw intelligence—it is human attention bandwidth. Today's frontier models possess the intelligence to implement 50 backlog features, but human engineers lack the supervisory bandwidth to oversee 50 simultaneous workflows.

Factory Missions shifts the paradigm: humans decide what to build (strategic scoping & requirements), and an ecosystem of specialized agents determines how to build it, operating autonomously for hours, days, or even weeks (longest production mission ran for 16 consecutive days).

"Tests written after implementation don't catch bugs. They confirm decisions. That is why Pre-Code Validation Contracts are the bedrock of multi-day missions."

— Luke (Lead Agent Harness, Factory)

2. The 3 Structural Inventions of Factory Missions

Invention 01

Pre-Code Contracts

Hundreds of behavioral assertions written by the Orchestrator before any code is produced, eliminating sunk-cost confirmation bias.

Invention 02 · Execution

Serial Features + Targeted Reads

Writes execute serially to guarantee zero Git merge conflicts, while read-only codebase searches and code reviews run concurrently.

Invention 03

Dual Adversarial Validators

Combines static Scrutiny Validators with interactive Computer Use QA agents that spawn live apps and click buttons to verify holistic UI rendering.

3. Comprehensive Concept Definitions (Module Glossary)

Master the exact terminology and operational concepts that govern autonomous multi-agent factory missions:

Mission Architecture

Factory Mission

A long-horizon, autonomous software engineering project executed by coordinated AI agents. Rather than single-file edits in chat, a mission can run for days, implementing complex epics, breaking down work into milestones, writing code, executing builds, and running QA tests without stopping.

Core Role 01

Mission Orchestrator (Lead Architect)

The high-reasoning agent responsible for strategic planning. It reads the human goal, scans the codebase, architects the implementation plan, writes the Pre-Code Validation Contracts, and delegates individual subtasks to implementation droids.

Core Role 02

Implementation Droid (Worker)

A fast, code-specialized agent tasked with executing a single isolated feature milestone. It modifies files, fixes syntax errors, and writes code to satisfy the Pre-Code Contract without concerning itself with overarching system governance.

Core Role 03

Validation Droid (Adversarial QA)

An independent quality-assurance agent that reviews pull requests against the Pre-Code Contract. Powered by a different model provider than the coder to avoid shared blind spots, it executes test suites, static analyzers, and UI browser tests to approve or reject the work.

Quality Assurance

Pre-Code Validation Contract

Writing test suites and behavioral assertions before any implementation code is written. If tests are written after coding, agents naturally write tests that validate whatever code they produced. Pre-code contracts eliminate this confirmation bias.

Execution Strategy

Serial Writes + Parallel Reads

A strict concurrency protocol: codebase queries, dependency scans, and documentation lookups run concurrently across multiple agents, but file edits and git commits are serialized into a single-file pipeline to completely prevent Git merge conflicts.

Model Allocation

"Droid Whispering" & Seat Assignment

Assigning distinct frontier models to roles based on cognitive strengths: heavy reasoning models (o1, Opus) to Orchestration; high-speed coding models (Claude 3.5 Sonnet) to Implementation; and rival models (GPT-4o) to Code Review to catch subtle provider biases.

Communication Protocol

Structured Contract Handoffs

Strict JSON or markdown schemas passed between agent stages. Instead of passing massive conversational contexts, the Orchestrator hands the Droid a precise task specification, file targets, and assertion criteria, ensuring zero context rot across multi-day runs.

4. The 3-Role Factory Lifecycle: Step-by-Step Flow

The lifecycle below traces how an autonomous mission travels through the 3-role factory architecture:

Step 1 · Strategic Ingestion & Contract Authoring

Orchestrator Scopes the Mission

The human defines the epic (e.g. "Migrate auth service to OAuth2 with Google/GitHub providers"). The Mission Orchestrator analyzes repository architecture and writes the Pre-Code Validation Contract (a complete test suite of 40 assertions defining success).

Step 2 · Contract Handoff & Droid Dispatch

Serialized Task Assignment

The Orchestrator packages Milestone 1 (Google OAuth endpoint) into a structured handoff schema and assigns it to an Implementation Droid with read/write access to target files.

Step 3 · Isolated Coding & Self-Correction

Droid Writes Code in Sandbox

The Implementation Droid edits the code, runs local linters and compiler passes, and executes the unit tests until all pass locally. It commits changes to an isolated feature branch and submits a handoff artifact.

Step 4 · Dual Adversarial Validation

Static Scrutiny & Computer Use QA

The Validation Droid (running an independent model) audits the branch. It runs the Pre-Code Contract assertions, performs security scans, and spins up a headless browser to interactively test the login UI. If tests fail, it writes an actionable critique and routes the branch back to the Droid.

Step 5 · Merge & Next Milestone

Orchestrator Verifies and Advances

Upon unanimous approval, the Orchestrator merges the feature branch to master, updates the global progress tracker, and proceeds to Milestone 2 (GitHub OAuth), continuing autonomously until the entire epic is complete.

Key Architectural Takeaways

  • "Droid Whispering" Multi-Provider Seat Assignment: Assign slow reasoning models to planning, fast code models to implementation, and a different model provider to validation to avoid shared training biases.
  • Structured Handoff Contracts: Zero context degradation over 16-day runs by enforcing mandatory milestone summaries of completed work, exit codes, and open issues.
  • Anti-Bitter-Lesson Architecture: Pure text prompts and skills drive 95% of orchestration logic, ensuring the system naturally improves with every new foundation model release.
