Executive Summary & Core Philosophy

Factory Missions: Long-Horizon Multi-Agent Systems

Field-tested insights from Luke (Creator of Goose, Lead Agent Harness at Factory): solving the human attention bottleneck in software engineering through multi-day autonomous agent ecosystems.

1. The New Bottleneck: Human Attention

The fundamental bottleneck in modern software engineering is no longer raw intelligence—it is human attention bandwidth. Today's frontier models possess the intelligence to implement 50 backlog features, but human engineers lack the supervisory bandwidth to oversee 50 simultaneous workflows.

Factory Missions shifts the paradigm: humans decide what to build (strategic scoping & requirements), and an ecosystem of specialized agents determines how to build it, operating autonomously for hours, days, or even weeks (longest production mission ran for 16 consecutive days).

"Tests written after implementation don't catch bugs. They confirm decisions. That is why Pre-Code Validation Contracts are the bedrock of multi-day missions."

— Luke (Lead Agent Harness, Factory)

2. The 3 Structural Inventions of Factory Missions

Invention 01

Pre-Code Contracts

Hundreds of behavioral assertions written by the Orchestrator before any code is produced, eliminating sunk-cost confirmation bias.

Invention 02 · Execution

Serial Features + Targeted Reads

Writes execute serially to guarantee zero Git merge conflicts, while read-only codebase searches and code reviews run concurrently.

Invention 03

Dual Adversarial Validators

Combines static Scrutiny Validators with interactive Computer Use QA agents that spawn live apps and click buttons to verify holistic UI rendering.

Key Architectural Takeaways

  • "Droid Whispering" Multi-Provider Seat Assignment: Assign slow reasoning models to planning, fast code models to implementation, and a different model provider to validation to avoid shared training biases.
  • Structured Handoff Contracts: Zero context degradation over 16-day runs by enforcing mandatory milestone summaries of completed work, exit codes, and open issues.
  • Anti-Bitter-Lesson Architecture: Pure text prompts and skills drive 95% of orchestration logic, ensuring the system naturally improves with every new foundation model release.
