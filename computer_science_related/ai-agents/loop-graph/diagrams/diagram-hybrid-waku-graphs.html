Production Agent Graphs: Triage & Gather

Real-world graph topologies from Waku Agent illustrating intent-routing triage graphs and parallel fan-out gather workflows.

1. Core Component Definitions

Exhaustive definitions of all workflow nodes, routing gateways, and parallel execution stages illustrated in the Waku Agent graphs:

Triage Graph (Intent Router) Graph 1 Topology

A conditional routing topology designed to protect system compute by intercepting incoming queries and separating lightweight direct queries from heavyweight autonomous agent tasks.

Intent Classifier Node Cognitive Routing

A fast, lightweight LLM or classifier evaluating query intent, complexity, and resource requirements (e.g. determining whether the user simply wants a calendar list or deep calendar reconciliation).

Decision Gateway Conditional Branch

The graph switch that routes execution down Path A (Fast Direct) for simple read operations without invoking an agent loop, or down Path B (Agent Loop) for multi-step reasoning.

Path A: Fast Direct Zero-Loop Path

Immediately formats and returns the calendar data retrieved by the concurrent calendar node, achieving sub-second responses without token waste or multi-turn latency.

Path B: Agent Loop Multi-Step Loop

Dispatches an autonomous multi-turn ReAct agent equipped with search, email, and task tools to synthesize complex cross-application insights.

Gather Graph (/gather) Graph 2 Topology

A fixed topological workflow designed for automated executive morning briefings, pulling cross-platform enterprise signals concurrently to eliminate sequential waiting.

4 Concurrent Ingestion Nodes Parallel Fan-Out

• Node 1 (Scan GitHub PRs): Pulls pending pull requests (1.2s).
• Node 2 (Competitor Web Research): Autonomous web search loop (3.8s).
• Node 3 (Google Calendar): Pulls user's daily agenda (0.4s).
• Node 4 (Memory Recall): SQLite query for durable facts and preferences (0.1s).

Synthesis & Eval Engine Fan-In Join

A centralized node that waits for all 4 concurrent branches to resolve, reconciles disparate payloads, filters irrelevancies, and outputs a structured markdown morning briefing.

Max-Latency Bounding Performance Law

By parallelizing the 4 ingestion streams, total graph latency is bounded by $\max(1.2, 3.8, 0.4, 0.1) \approx 3.8\text{s}$ instead of the sequential sum $1.2 + 3.8 + 0.4 + 0.1 = 5.5\text{s}$, saving over 30% execution time.

2. Step-by-Step Diagram Flow Walkthrough

Tracing the execution paths and conditional logic of both production topologies:

1
Triage Graph — Step 1: Input Split

The user inputs "WHAT'S UP TODAY?". The graph initiates two concurrent branches: Branch A fetches raw calendar data immediately, while Branch B passes the prompt to the Intent Classifier.

2
Triage Graph — Step 2: Gateway Decision

The Intent Classifier evaluates the complexity of the request and sends the classification signal to the Decision Gateway:
• If the user only asked for a schedule check, it routes to Path A (Fast Direct), instantly returning the calendar list.
• If the query requires complex cross-referencing, it routes to Path B (Agent Loop) to trigger a multi-tool reasoning cycle.

3
Gather Graph — Step 1: Trigger & 4-Way Fan-Out

A scheduled cron or explicit prompt fires /gather. The graph dispatcher launches all 4 worker nodes simultaneously across asynchronous tasks: GitHub PR scanner, Web Research agent, Calendar fetcher, and Memory retriever.

4
Gather Graph — Step 2: Asynchronous Execution

Memory Recall finishes first in 0.1s; Google Calendar finishes in 0.4s; GitHub PRs finish in 1.2s. Meanwhile, Competitor Web Research autonomously runs its internal multi-turn search loop, completing in 3.8s without blocking the other coroutines.

5
Gather Graph — Step 3: Fan-In Synthesis

Once Node 2 finishes, the coral fan-in join line triggers. All 4 payloads are piped into the Synthesis & Eval Engine, which generates the comprehensive Morning Brief in 3.8s total elapsed time.

3. Concrete Implementation Blueprint

A runnable Python blueprint implementing both the Triage Router and the Parallel Gather Graph:

waku_production_graphs.py — Triage & Gather Graph Orchestration Python 3.11+ / asyncio 
import asyncio
import time
from typing import Dict, Any, List

# =============================================================
# TOPOLOGY 1: TRIAGE GRAPH (Intent Classifier & Gateway)
# =============================================================
async def fetch_calendar_quick() -> List[str]:
    await asyncio.sleep(0.3)
    return ["09:00 AM - Sprint Standup", "01:00 PM - 1-on-1 with Lead"]

async def classify_intent(query: str) -> str:
    await asyncio.sleep(0.2)
    # Simple heuristic or lightweight LLM call
    if "research" in query.lower() or "why" in query.lower():
        return "HEAVY_AGENT_LOOP"
    return "SIMPLE_DIRECT"

async def run_triage_graph(query: str) -> str:
    print(f"\n[TRIAGE] Processing query: '{query}'")
    # Step 1: Concurrently start calendar fetch and intent classification
    cal_task = asyncio.create_task(fetch_calendar_quick())
    intent_task = asyncio.create_task(classify_intent(query))
    
    cal_data, intent = await asyncio.gather(cal_task, intent_task)
    print(f"[TRIAGE] Decision Gateway received intent: '{intent}'")
    
    # Step 2: Conditional Branching
    if intent == "SIMPLE_DIRECT":
        print("  └─ Path A: Returning Fast Direct calendar list (0 loop turns)")
        return f"Today's Schedule:\n- " + "\n- ".join(cal_data)
    else:
        print("  └─ Path B: Dispatching Multi-Step Autonomous Agent Loop...")
        await asyncio.sleep(1.5)  # Multi-step reasoning simulation
        return f"Detailed Strategic Analysis for today: {cal_data}"

# =============================================================
# TOPOLOGY 2: GATHER GRAPH (Parallel Morning Brief)
# =============================================================
async def node_github_prs() -> str:
    await asyncio.sleep(1.2)
    return "PR #88: Merge Conflict in Auth Handler"

async def node_competitor_web_loop() -> str:
    # Inner agent loop executing 2 turns
    await asyncio.sleep(1.9)
    await asyncio.sleep(1.9)
    return "Competitor launched Delta Attention inference engine"

async def node_calendar_events() -> str:
    await asyncio.sleep(0.4)
    return "3 meetings today: Standup, Design Review, Demo"

async def node_memory_recall() -> str:
    await asyncio.sleep(0.1)
    return "User Goal: Complete AI agent curriculum review"

async def run_gather_graph() -> str:
    print(f"\n[GATHER] Trigger '/gather' received. Fanning out 4 concurrent nodes...")
    t0 = time.perf_counter()
    
    # Parallel Fan-Out
    github_res, web_res, cal_res, mem_res = await asyncio.gather(
        node_github_prs(),
        node_competitor_web_loop(),
        node_calendar_events(),
        node_memory_recall()
    )
    
    # Fan-In Synthesis Engine
    print("[GATHER] Aggregating payloads in Synthesis & Eval Engine...")
    await asyncio.sleep(0.2)
    brief = (
        f"╔══════════════════════════════════════════════════════════════╗\n"
        f"║                    EXECUTIVE MORNING BRIEF                   ║\n"
        f"╠══════════════════════════════════════════════════════════════╣\n"
        f"║ GitHub:   {github_res:<50} ║\n"
        f"║ Research: {web_res:<50} ║\n"
        f"║ Schedule: {cal_res:<50} ║\n"
        f"║ Memory:   {mem_res:<50} ║\n"
        f"╚══════════════════════════════════════════════════════════════╝"
    )
    elapsed = time.perf_counter() - t0
    print(f"[GATHER] Graph completed in {elapsed:.2f}s (Max node latency: 3.8s)")
    return brief

if __name__ == "__main__":
    # Test Path A (Simple Direct)
    print(asyncio.run(run_triage_graph("What's up today?")))
    # Test Path B (Heavy Agent Loop)
    print(asyncio.run(run_triage_graph("Why did PR #42 fail and what's up today?")))
    # Test Gather Workflow
    print(asyncio.run(run_gather_graph()))
