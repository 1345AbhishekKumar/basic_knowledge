Paradigm Comparison · Diagram Design

Loop Engineering vs Graph Engineering

Contrasting dynamic step-by-step discovery against predefined topological workflows—and showing how they coexist in production AI harnesses.

1. Core Component Definitions

Exhaustive definitions of every element, node, and property illustrated in the Loop vs Graph architectural comparison diagram:

User Goal / Task Loop Entry

The high-level prompt provided by the user (e.g. "FIX PR #42 ON GITHUB"). The execution path, required tools, and number of iterations are entirely unknown prior to runtime.

LLM Reasoner Loop Brain

The cognitive engine evaluating the conversation history, asking "Do I need a tool?", dynamically selecting a single tool invocation, and observing the environment's response.

Step 1: git checkout & test Loop Turn 1

The first environmental interaction. Runs git commands and test suites, capturing raw error stack traces to feed back into the Reasoner context via the dashed feedback line.

Step 2: search codebase Loop Turn 2

The second environmental interaction. Greps and navigates repository files based on the stack trace, isolating the buggy function and returning line context to the model.

Step 3: patch & commit Loop Turn 3

The remediation step. Writes code fixes, reruns tests, verifies that all assertions pass, and prepares a git commit confirming goal completion.

Final Answer / Resolution Loop Exit

The terminal state emitted to the user once all termination criteria are satisfied. Cumulative wall-clock latency is the direct sum of every sequential tool invocation.

Workflow Trigger (/GATHER) Graph Entry

A deterministic event (such as a slash command or scheduled cron) triggering a workflow whose operational graph and dependencies are pre-architected and fixed.

Node 1: Scan GitHub PRs Parallel Branch

A non-blocking API call querying the GitHub REST API for pending pull requests and reviews. Completes in 1.2s of network latency.

Node 2: Web Search (Inner Loop) Embedded Loop

A specialized node encapsulating an autonomous multi-turn ReAct agent. It runs iterative search queries, scrapes web pages, and synthesizes competitor findings over 3.8s without blocking sister branches.

Node 3: Check Google Calendar Parallel Branch

A deterministic external integration pulling the authenticated user's schedule for the day. Completes concurrently in 0.4s.

Node 4: Retrieve Semantic Memory Parallel Branch

A fast local SQLite vector or key-value lookup retrieving durable user preferences and active mission goals. Completes in 0.1s.

Synthesis & Eval Node Fan-In Join

The convergence junction where all 4 streams are joined, evaluated for consistency, and assembled into a structured morning briefing document in approximately $\max(1.2, 3.8, 0.4, 0.1) \approx 3.8\text{s}$.

2. Step-by-Step Diagram Flow Walkthrough

Tracing the directional flow, feedback loops, and parallel branching in both panels of the diagram:

1
Loop Panel — Step 1: Input to Cognitive Evaluation

The User Goal ("FIX PR #42 ON GITHUB") enters the LLM Reasoner. Because the bug location and fix are unknown, the model cannot plan the entire sequence; it selects only the immediate next tool: git checkout & test.

2
Loop Panel — Step 2: Environmental Feedback Loops

The tool returns error logs. The dashed feedback line channels these logs back to the Reasoner context. The Reasoner analyzes the stack trace and dynamically invokes search codebase. Findings flow back again, prompting the Reasoner to invoke patch & commit.

3
Loop Panel — Step 3: Terminal Resolution

With tests passing, the Reasoner determines no more tools are required and routes down to the Final Answer / Resolution. The execution was completely sequential; total wall-clock time was the linear sum of all three tool calls.

4
Graph Panel — Step 1: Deterministic Fan-Out Dispatch

The /GATHER trigger fires. Instead of sequentially invoking one tool after another, the graph engine uses the 4 coral fan-out arrows to launch Node 1 (GitHub PRs), Node 2 (Web Search), Node 3 (Calendar), and Node 4 (Memory Recall) simultaneously in separate coroutines.

5
Graph Panel — Step 2: Concurrency with Embedded Sub-Loop

While Nodes 1, 3, and 4 finish their deterministic I/O calls rapidly (0.1s - 1.2s), Node 2 autonomously runs an Inner Loop for 3.8s. The parent graph cleanly coordinates this without thread starvation or premature termination.

6
Graph Panel — Step 3: Fan-In Aggregation & Synthesis

The coral fan-in arrow triggers as soon as the slowest node (Node 2) resolves. Payloads from all 4 nodes are passed simultaneously into the Synthesis & Eval Node, yielding a final Morning Brief in 3.8s total wall-clock time.

3. Concrete Implementation Blueprint

A runnable Python blueprint contrasting the sequential tool loop against the concurrent topological graph harness:

loop_vs_graph_comparison.py — Production Harness Demonstration Python 3.11+ / asyncio 
import asyncio
import time
from typing import Dict, Any, List

# =============================================================
# PARADIGM A: SEQUENTIAL LOOP (Discovery / Debugging)
# =============================================================
async def run_discovery_loop(task: str) -> Dict[str, Any]:
    print(f"\n[LOOP] Starting discovery loop for: '{task}'")
    start = time.perf_counter()
    context = {"task": task, "logs": [], "status": "in_progress"}
    
    # Step 1: Checkout & test
    print("  └─ [Turn 1] Executing git checkout & test...")
    await asyncio.sleep(1.0)
    context["logs"].append("AssertionError: expected 200 got 500 in auth.py:42")
    
    # Step 2: Search codebase
    print("  └─ [Turn 2] Analyzing error logs -> Searching codebase...")
    await asyncio.sleep(1.2)
    context["logs"].append("Found missing token validation in auth.py:42")
    
    # Step 3: Patch & commit
    print("  └─ [Turn 3] Applying patch & verifying test...")
    await asyncio.sleep(0.8)
    context["status"] = "resolved"
    
    duration = time.perf_counter() - start
    print(f"[LOOP] Goal complete in {duration:.2f}s (Sequential Sum: 1.0 + 1.2 + 0.8)")
    return context

# =============================================================
# PARADIGM B: TOPOLOGICAL GRAPH (Parallel Fan-Out / Fan-In)
# =============================================================
async def node_github() -> str:
    await asyncio.sleep(1.2)
    return "GitHub: 3 open PRs (PR #42 ready for merge)"

async def node_web_inner_loop() -> str:
    # Inner agent loop running 2 turns inside this graph node
    await asyncio.sleep(1.9)
    await asyncio.sleep(1.9)
    return "Web Intel: Competitor released KDA attention model"

async def node_calendar() -> str:
    await asyncio.sleep(0.4)
    return "Calendar: 2 meetings today at 10:00 AM and 3:00 PM"

async def node_memory() -> str:
    await asyncio.sleep(0.1)
    return "Memory: User prefers high-level bullet summaries"

async def run_topological_graph(trigger: str) -> str:
    print(f"\n[GRAPH] Trigger received: '{trigger}' -> Fanning out 4 concurrent nodes...")
    start = time.perf_counter()
    
    # Concurrent Fan-Out
    pr_res, web_res, cal_res, mem_res = await asyncio.gather(
        node_github(),
        node_web_inner_loop(),
        node_calendar(),
        node_memory()
    )
    
    # Fan-In Synthesis Node
    print("[GRAPH] All nodes completed -> Synthesizing morning brief...")
    await asyncio.sleep(0.2)
    brief = (
        f"=== SYNTHESIS OUTPUT ===\n"
        f"• {pr_res}\n"
        f"• {web_res}\n"
        f"• {cal_res}\n"
        f"• {mem_res}"
    )
    
    duration = time.perf_counter() - start
    print(f"[GRAPH] Completed in {duration:.2f}s (Bounded by Max(1.2, 3.8, 0.4, 0.1) + 0.2s)")
    return brief

if __name__ == "__main__":
    asyncio.run(run_discovery_loop("Fix PR #42"))
    brief = asyncio.run(run_topological_graph("/gather"))
    print(brief)
