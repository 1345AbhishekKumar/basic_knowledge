The 3-Dimensional AI Agent Memory Taxonomy

Every agent memory system is defined by three fundamental axes: how information is structurally represented, how the runtime locates it, and how truth is maintained over time.

1. Core Component Definitions

Exhaustive definitions across the 3 structural axes defining AI agent memory engineering:

Plain Text & Markdown Axis 1: Storage

Raw file storage (MEMORY.md, SOUL.md). Transparent, human-editable, and version-controllable with zero infrastructure dependencies. Best for personal developer agents.

Relational Tables & Rows Axis 1: Storage

Structured ACID tables (SQLite state.db, PostgreSQL). Stores timestamped conversation turns, message schemas, and metadata. Guarantees transactional logging.

Vector Embeddings + Meta Axis 1: Storage

Dense numerical vectors (e.g. 1536-dimensional floats in pgvector or Pinecone) mapped to text chunks. Powers approximate semantic retrieval across phrasing variations.

Relational & Temporal Graphs Axis 1: Storage

Entity-relationship networks (Zep, Mem0 Graph) connecting nodes with semantic predicates (e.g. Alice → works_at → AcmeCorp) with temporal validity bounds for explicit reasoning.

Preloaded Context (Do Nothing) Axis 2: Retrieval

Zero runtime retrieval latency. The entire memory file is injected directly into the system prompt. Ideal for small, high-value fact bases under 2,000 tokens.

Keyword & Lexical Search Axis 2: Retrieval

Full-text indexing (SQLite FTS5, BM25 ranking). Fast sub-millisecond search for exact identifiers, error codes, file paths, and function names.

Semantic Vector Search Axis 2: Retrieval

Cosine similarity and Approximate Nearest Neighbor (ANN) search over embeddings. Retrieves conceptually related passages even when vocabulary does not overlap.

Hybrid GraphRAG Traversal Axis 2: Retrieval

Two-stage retrieval: vector search identifies seed entity nodes, followed by multi-hop graph edge traversal to extract structured relationships and temporal context.

Basic Mutation Gates Axis 3: Lifecycle

Deterministic update decisions (ADD, DELETE, OVERWRITE, NOOP) executed before committing a fact to storage to prevent redundant writes.

Temporal Invalidation (Supersede) Axis 3: Lifecycle

Non-destructive evolution. When a fact changes (e.g. dinner shifted from 7PM to 9PM), the old record is marked with an expiration timestamp while the new record becomes active, preserving velocity history.

Source Provenance (Attribute) Axis 3: Lifecycle

Cryptographic or schema tracking linking every fact to its origin: user prompt, tool execution output, web scrape, or subagent message, establishing a trust hierarchy.

Consolidation / "Dreaming" Axis 3: Lifecycle

Scheduled or idle-time auxiliary LLM worker that aggregates episodic turn logs, deduplicates facts, resolves conflicts, and produces a consolidated knowledge base.

2. Step-by-Step Diagram Flow Walkthrough

Tracing the three organizational pillars across the memory taxonomy diagram:

1
Column 1: Selecting the Underlying Storage Representation

The architect evaluates data persistence requirements: from lightweight human-editable markdown (MEMORY.md), to structured ACID tables (SQLite state.db), vector embeddings, up to interconnected entity-relationship Knowledge Graphs.

2
Column 2: Determining the Runtime Retrieval Strategy

Based on the storage choice, the runtime selects its access mechanism: preloading all facts (zero latency overhead), running lexical FTS5 queries for exact keywords, executing vector cosine similarity for conceptual recall, or traversing GraphRAG edges for relational context.

3
Column 3: Enforcing Memory Lifecycle and Maintenance

To prevent memory corruption and context entropy, the harness applies lifecycle protocols: mutation gates resolve deltas, temporal superseding preserves history, source attribution verifies trustworthiness, and the offline Dreaming daemon distills raw turns into consolidated knowledge.

3. Concrete Implementation Blueprint

A Python class implementing the 3-axis memory taxonomy with SQLite storage, FTS5 lexical retrieval, and temporal invalidation:

memory_taxonomy_engine.py — 3-Axis Memory Harness Implementation Python 3.11+ / SQLite FTS5 
import sqlite3
import time
from typing import List, Dict, Any, Optional

class MemoryTaxonomyEngine:
    def __init__(self, db_path=":memory:"):
        self.conn = sqlite3.connect(db_path)
        self.setup_storage()

    # =========================================================
    # AXIS 1: STORAGE MODEL (Relational Schema + FTS5 Index)
    # =========================================================
    def setup_storage(self):
        with self.conn:
            # Relational fact store with temporal validity columns
            self.conn.execute("""
                CREATE TABLE IF NOT EXISTS facts (
                    id INTEGER PRIMARY KEY AUTOINCREMENT,
                    subject TEXT,
                    predicate TEXT,
                    object TEXT,
                    provenance TEXT,
                    valid_from REAL,
                    valid_to REAL
                )
            """)
            # FTS5 Virtual Table for Lexical / Keyword Search
            self.conn.execute("""
                CREATE VIRTUAL TABLE IF NOT EXISTS facts_fts USING fts5(
                    subject, predicate, object, content='facts', content_rowid='id'
                )
            """)

    # =========================================================
    # AXIS 3: LIFECYCLE (Mutation Gate & Temporal Superseding)
    # =========================================================
    def record_fact(self, subject: str, predicate: str, object_val: str, source: str = "user"):
        now = time.time()
        with self.conn:
            # Step 1: Temporal Invalidation - Supersede previous active fact
            cur = self.conn.execute(
                "SELECT id FROM facts WHERE subject = ? AND predicate = ? AND valid_to IS NULL",
                (subject, predicate)
            )
            old_rows = cur.fetchall()
            for r in old_rows:
                self.conn.execute("UPDATE facts SET valid_to = ? WHERE id = ?", (now, r[0]))
                print(f"[Lifecycle] Superseded fact id={r[0]} ({subject} {predicate}) at ts={now}")

            # Step 2: Insert new active record
            cur = self.conn.execute(
                """INSERT INTO facts (subject, predicate, object, provenance, valid_from, valid_to) 
                   VALUES (?, ?, ?, ?, ?, NULL)""",
                (subject, predicate, object_val, source, now)
            )
            new_id = cur.lastrowid
            
            # Step 3: Update FTS index
            self.conn.execute(
                "INSERT INTO facts_fts (rowid, subject, predicate, object) VALUES (?, ?, ?, ?)",
                (new_id, subject, predicate, object_val)
            )
            print(f"[Lifecycle] Added active truth id={new_id}: '{subject} {predicate} {object_val}' (Source: {source})")

    # =========================================================
    # AXIS 2: RETRIEVAL MODEL (FTS5 Lexical Search & Active Fetch)
    # =========================================================
    def retrieve_by_keyword(self, query: str) -> List[Dict[str, Any]]:
        """Axis 2: Lexical keyword search using SQLite FTS5."""
        cursor = self.conn.execute(
            """SELECT f.subject, f.predicate, f.object, f.provenance, f.valid_to
               FROM facts f
               JOIN facts_fts ON f.id = facts_fts.rowid
               WHERE facts_fts MATCH ?""",
            (query,)
        )
        results = []
        for row in cursor.fetchall():
            status = "ACTIVE" if row[4] is None else "SUPERSEDED"
            results.append({
                "fact": f"{row[0]} {row[1]} {row[2]}",
                "source": row[3],
                "status": status
            })
        return results

if __name__ == "__main__":
    engine = MemoryTaxonomyEngine()
    
    # Store initial fact
    engine.record_fact("Meeting", "scheduled_at", "18:00", source="calendar_api")
    
    # Update fact (demonstrating Temporal Superseding)
    time.sleep(0.01)
    engine.record_fact("Meeting", "scheduled_at", "20:00", source="user_slack")
    
    # Retrieve via Keyword search
    print("\n--- Keyword Search for 'Meeting' ---")
    matches = engine.retrieve_by_keyword("Meeting")
    for m in matches:
        print(f"• [{m['status']}] {m['fact']} (Provenance: {m['source']})")
