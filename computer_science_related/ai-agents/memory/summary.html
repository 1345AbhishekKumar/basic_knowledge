Executive Summary & Core Philosophy

AI Agent Memory Architecture

Why Large Language Model inference is stateless, how agent harnesses engineer persistent continuity, and why long-term memory is the ultimate asset in autonomous AI systems.

1. The Stateless LLM Reality

At their computational core, raw Large Language Model (LLM) API calls do not retain long-term state or update their weights between inference requests. Every forward pass across a transformer is mathematically isolated from past prompts.

When advanced developer agents such as ChatGPT, Claude Code, Hermes Agent, or Waku Agent remember past conversations, architectural decisions, user preferences, and tools, it is because an engineered Agent Harness surrounds the model with an explicit memory management subsystem.

"The agent harness is what turns a one-off prompt into an enduring partner. Base models and prompts will get commoditized; the memory system you accumulate, curate, and preserve is what lasts forever."

— Core Architectural Tenet

2. The Agent Harness Runtime Environment

A production agent harness orchestrates two concurrent feedback loops: high-velocity online execution (tool calling, subagent delegation, user I/O) and asynchronous offline persistence (episodic turn logging, fact distillation, and memory dreaming).

3. The Three Cognitive Pillars

Regardless of whether your backend uses plain markdown files or high-dimensional temporal graphs, a robust cognitive system is structured into three fundamental pillars:

Pillar 01

Procedural Memory

Operational rules, prompts, execution skills, and behavioural guidelines (e.g. SOUL.md). Instructs the agent on how to act and reason.

Pillar 02 · Core

Semantic Memory

Durable, consolidated facts, domain truths, and user preferences (e.g. MEMORY.md). Instructs the agent on what is true across all sessions.

Pillar 03

Episodic Memory

Timestamped interaction history and conversation logs (e.g. SQLite state.db). Instructs the agent on what occurred and when.

Key Architectural Principles

  • Memory is the Ultimate Asset: Models and prompt tricks fluctuate with every release cycle. The accumulated, structured knowledge graph or consolidated fact base is what retains user value over time.
  • Separate Online Interaction from Dreaming: Keep online turn generation fast, lean, and responsive. Delegate heavy fact consolidation, deduplication, and truth reconciliation to scheduled background or idle-time auxiliary daemons.
  • Prefer Non-Destructive Invalidation (Superseding): Never blindly overwrite or delete historical data points when values change. Maintain validity time ranges so the agent preserves velocity metrics and audit trails.

4. Comprehensive Concept Definitions

Precise architectural definitions of every core concept, system paradigm, and component appearing in the AI Agent Memory curriculum:

Procedural Memory Pillar 01

The operational instructions, system personas (SOUL.md), guidelines, and specialized skill workflows that instruct the agent on how to act, execute commands, and solve tasks.

Semantic Memory Pillar 02 (Core)

Durable, distilled facts, verified enterprise domain knowledge, and user preferences (MEMORY.md). Informs the agent on what is true across sessions without re-reading raw chat histories.

Episodic Memory Pillar 03

Timestamped logs of past conversations, raw user turns, and tool interaction traces (SQLite state.db). Records what occurred, in what sequence, and at what exact time.

Active Working Memory Context Window RAM

The immediate prompt context window budget available for the current inference turn. Dynamically assembled by injecting the system persona, active skills, distilled facts, and recent conversation turns.

Agent Execution Loop Online Runtime

The high-velocity online loop that evaluates user input, decides tool invocations, delegates tasks to subagents, and synthesizes final responses before logging telemetry to episodic storage.

Consolidation Engine ("Dreaming") Offline Daemon

An asynchronous background process powered by an auxiliary LLM. Periodically scans episodic logs, reconciles conflicting statements, prunes redundant noise, and writes clean facts to durable semantic storage.

Retrieval Gate Context Filter

The algorithmic gatekeeper that balances context window token limits. Selectively retrieves relevant procedural rules and semantic facts while suppressing irrelevant historical data.

Temporal Invalidation Lifecycle Protocol

A non-destructive truth maintenance pattern. Instead of deleting outdated facts, it assigns validity time ranges (valid_from, valid_to) so current queries see active truth while retaining historical audit trails.

5. Step-by-Step Diagram Flow Walkthrough

Tracing the dual-loop data flow depicted in Figure 1.0 (Agent Harness Runtime & Memory Loop):

1
Step 1: Selective Memory Retrieval into Working RAM

Before generating a response, the Retrieval Gate queries Persistent Cognitive Memory (Procedural skills and Semantic facts). It filters relevant records to prevent context window overflow and constructs the Active Working Memory payload.

2
Step 2: Prompt Dispatch to Execution Loop

The assembled prompt (Persona + Active Skills + Injected Facts + User Turn) flows along the ink arrow into the Agent Execution Loop. The model initiates multi-turn tool calling, subagent delegation, or direct answer formulation.

3
Step 3: Episodic Turn Logging

As the execution loop completes, the harness logs the full turn record (user prompt, tool calls, tool responses, token telemetry) down the muted arrow into Episodic Storage (SQLite state.db).

4
Step 4: Offline Consolidation ("Dreaming")

During user idle time or on a scheduled message interval, the Consolidation Daemon triggers. An auxiliary LLM ingests recent episodic turn records to detect new user preferences, updated facts, and completed goals.

5
Step 5: Semantic Memory Distillation

The daemon distills extracted facts, resolves conflicting timestamps (superseding older values), and updates Persistent Cognitive Memory (MEMORY.md and vector/graph stores). This closes the cognitive loop, ensuring future sessions start with upgraded knowledge.

6. Concrete Implementation Blueprint

A runnable Python implementation of a 3-pillar memory system featuring episodic logging, semantic fact management with temporal validity ranges, and an asynchronous dreaming consolidation engine:

agent_memory_harness.py — 3-Pillar Cognitive System with Dreaming Loop Python 3.11+ / SQLite 
import sqlite3
import time
import asyncio
from dataclasses import dataclass
from typing import List, Optional, Dict, Any

# =============================================================
# PILLAR 1: PROCEDURAL MEMORY (Skills & Soul Persona)
# =============================================================
class ProceduralMemory:
    def __init__(self):
        self.soul = "You are a senior software architect who gives concise, test-driven answers."
        self.skills = {
            "git_commit": "SOP: Use conventional commits format.",
            "sql_query": "SOP: Always parameterize queries; never concatenate strings."
        }

    def get_system_prompt(self, relevant_skill: Optional[str] = None) -> str:
        prompt = f"System Persona: {self.soul}"
        if relevant_skill and relevant_skill in self.skills:
            prompt += f"\nActive Skill: {self.skills[relevant_skill]}"
        return prompt

# =============================================================
# PILLAR 2: SEMANTIC MEMORY (Durable Facts + Temporal Validity)
# =============================================================
@dataclass
class SemanticFact:
    entity: str
    attribute: str
    value: str
    valid_from: float
    valid_to: Optional[float] = None  # None = actively true

class SemanticMemoryStore:
    def __init__(self):
        self.facts: List[SemanticFact] = []

    def set_fact(self, entity: str, attribute: str, value: str):
        now = time.time()
        # Supersede existing active fact for this entity & attribute
        for fact in self.facts:
            if fact.entity == entity and fact.attribute == attribute and fact.valid_to is None:
                fact.valid_to = now
                print(f"[Semantic Store] Superseded: {entity}.{attribute} was '{fact.value}' (valid until {now})")
        
        # Insert new active fact
        new_fact = SemanticFact(entity=entity, attribute=attribute, value=value, valid_from=now)
        self.facts.append(new_fact)
        print(f"[Semantic Store] Stored Active Fact: {entity}.{attribute} = '{value}'")

    def get_active_facts(self) -> List[str]:
        return [f"{f.entity} {f.attribute}: {f.value}" for f in self.facts if f.valid_to is None]

# =============================================================
# PILLAR 3: EPISODIC MEMORY (SQLite Interaction Logs)
# =============================================================
class EpisodicMemoryStore:
    def __init__(self, db_path=":memory:"):
        self.conn = sqlite3.connect(db_path)
        self.create_tables()

    def create_tables(self):
        with self.conn:
            self.conn.execute("""
                CREATE TABLE IF NOT EXISTS conversation_turns (
                    id INTEGER PRIMARY KEY AUTOINCREMENT,
                    session_id TEXT,
                    role TEXT,
                    content TEXT,
                    created_at REAL
                )
            """)

    def log_turn(self, session_id: str, role: str, content: str):
        with self.conn:
            self.conn.execute(
                "INSERT INTO conversation_turns (session_id, role, content, created_at) VALUES (?, ?, ?, ?)",
                (session_id, role, content, time.time())
            )

    def get_unconsolidated_turns(self, limit: int = 10) -> List[Dict[str, Any]]:
        cursor = self.conn.execute(
            "SELECT id, role, content FROM conversation_turns ORDER BY id DESC LIMIT ?", (limit,)
        )
        return [{"id": row[0], "role": row[1], "content": row[2]} for row in cursor.fetchall()]

# =============================================================
# CONSOLIDATION ENGINE ("Dreaming Daemon")
# =============================================================
class MemoryHarness:
    def __init__(self):
        self.procedural = ProceduralMemory()
        self.semantic = SemanticMemoryStore()
        self.episodic = EpisodicMemoryStore()

    async def dream_consolidation(self):
        """Asynchronous daemon that extracts durable facts from episodic turns."""
        print("\n[Dreaming Daemon] Scanning episodic history for memory consolidation...")
        turns = self.episodic.get_unconsolidated_turns()
        
        # Simulated distillation logic: extract facts from user statements
        for turn in turns:
            if turn["role"] == "user" and "my favorite framework is" in turn["content"].lower():
                val = turn["content"].split("is")[-1].strip()
                self.semantic.set_fact("user", "favorite_framework", val)
            elif turn["role"] == "user" and "i moved to" in turn["content"].lower():
                val = turn["content"].split("to")[-1].strip()
                self.semantic.set_fact("user", "city", val)

        await asyncio.sleep(0.5)
        print("[Dreaming Daemon] Consolidation complete. Semantic truth updated.\n")

    def run_turn(self, session_id: str, user_input: str) -> str:
        # Step 1: Log episodic user turn
        self.episodic.log_turn(session_id, "user", user_input)
        
        # Step 2: Assemble Active Working Memory
        active_facts = self.semantic.get_active_facts()
        system_prompt = self.procedural.get_system_prompt("git_commit")
        
        print(f"--- [Active Working Memory] ---")
        print(f"System: {system_prompt}")
        print(f"Facts Injected: {active_facts}")
        print(f"User Input: {user_input}")
        
        # Step 3: Simulate model response
        response = f"Acknowledged. I understand your context."
        self.episodic.log_turn(session_id, "assistant", response)
        return response

# =============================================================
# DEMO EXECUTION
# =============================================================
async def main():
    harness = MemoryHarness()
    
    # Session 1: User provides initial facts
    harness.run_turn("sess_1", "Hello, my favorite framework is PyTorch.")
    harness.run_turn("sess_1", "Also, I moved to Zurich.")
    
    # Run offline Dreaming loop to distill facts into Semantic Memory
    await harness.dream_consolidation()
    
    # Session 2: User updates a fact (Zurich -> San Francisco)
    harness.run_turn("sess_2", "Actually, I moved to San Francisco this week.")
    
    # Run Dreaming loop again to demonstrate Temporal Invalidation
    await harness.dream_consolidation()
    
    # Final check of active truths
    print("=== Current Active Semantic Truths ===")
    for fact in harness.semantic.get_active_facts():
        print(f"• {fact}")

if __name__ == "__main__":
    asyncio.run(main())
