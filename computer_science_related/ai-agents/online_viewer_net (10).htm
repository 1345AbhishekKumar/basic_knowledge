01 / Core idea

Model ≠ Agent.

The model is the brain, but the brain alone is not the operating system. The transcript frames a model as a function that receives input and generates output, while the agent adds an execution loop and surrounding software.

The critical mental model

A model does not inherently search the web, read files, execute arbitrary code, or maintain the entire runtime state of a long-running workflow.

Model Input → inference → output
+
Agent runtime Loop + tools + context + execution + state

What changes?

With tools The system can interact with external capabilities.

05 / Skills

Tools tell the agent what it can do. Skills tell it how to do it.

A skill is an instruction document describing a repeatable procedure, expected format, tools, and known pitfalls.

skill.md 
# Research Report Skill

## Goal
Create a structured research report.

## Procedure
1. Identify the research question.
2. Gather relevant sources.
3. Use the web search tool.
4. Check important facts.
5. Structure the results.
6. Render the final artifact.

## Rules
- Follow the report format.
- Cite important claims.
- Check tool failures.
- Avoid unnecessary context.

## Output
Produce a self-contained report.

Think of it as an SOP.

The transcript compares a skill to an onboarding document or standard operating procedure given to a new employee.

Skill Instructions + workflow + constraints
→
Agent behavior Repeatable task execution
Skills can be loaded when relevant rather than injecting every possible procedure into every model context.
06 / Sandbox

Give the agent a disposable computer.

Agents may need to run code, process files, analyze data, or build artifacts. The sandbox isolates that execution from the primary machine.

07 / Sub-agents

One agent does not have to do everything.

The production layer can split a larger task across multiple workers so different pieces of work run in parallel.

Main Agent Decomposes the task
Researcher A Find technical information
Researcher B Compare models
Researcher C Validate benchmarks
Parallel execution: independent research tasks can be delegated to workers simultaneously and their results can later be combined.

13 / Checklist

Design the agent before you build it.

Use the checklist to reason about the system as an architecture, not merely as a prompt.

✓
Define the goal What job is the agent actually responsible for?
✓
Select the model Choose based on reasoning, latency, cost, availability, and deployment constraints.
✓
Design the harness Decide how context, state, actions, and retries will be managed.
✓
Identify required tools Web, APIs, files, database, calendar, shell, or other capabilities.
✓
Define skills Encode repeatable procedures instead of relying on vague prompting.
✓
Isolate execution Determine what belongs in a sandbox or other controlled execution environment.
✓
Decide where humans approve Sensitive or irreversible actions may need a human checkpoint.
✓
Define observability Log actions, tool calls, outputs, failures, latency, and cost.
✓
Consider sub-agents Parallelize independent pieces of larger workflows.
