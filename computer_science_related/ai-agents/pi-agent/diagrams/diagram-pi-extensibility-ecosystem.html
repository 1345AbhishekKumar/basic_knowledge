Pi Agent Extensibility & Ecosystem Tiers

How Pi Agent enables users to construct their own powerful harnesses via 4 clean extensibility layers: Skills, TypeScript Extensions, Distributable Packages, and Headless Subagent Delegation.

FIGURE 4.0 — THE 4 EXTENSIBILITY TIERS OF PI AGENT

Detailed Architectural Explanations

Tier 01 & 02

Skills vs. TypeScript Extensions

Skills are markdown SOPs that instruct the model how to query existing APIs. Extensions are native TypeScript files stored in ~/.pi/extensions/ that inject brand-new, executable tool functions into Pi's runtime without the heavy overhead of external MCP daemon processes.

Tier 04 · The Universal Subagent

Plugging Pi into Outer Harnesses

Because Pi Agent has a lightning-fast CLI interface (pi -p), it serves as the default headless coding engine for outer agent orchestrators like Waku Agent and OpenClaw. The outer agent manages memories, gateways, and evals, while delegating code synthesis to Pi Agent.

1. The 4 Extensibility Tier Definitions

Detailed architectural definitions for each tier in Pi Agent's extensibility hierarchy (Figure 4.0):

Tier 01 · Procedural Behavior

Skills (.agent/skills/*.md)

Pure markdown standard operating procedures (SOPs) placed in the local repo. They define behavioral guidelines, documentation lookups, and API schemas (e.g., PokéAPI endpoints) without introducing executable runtime code or dependency risk.

Tier 02 · Executable Tools

Extensions (~/.pi/extensions/*.ts)

Lightweight TypeScript files that register new custom tool functions directly into Pi's runtime (such as typeMatch()). They execute in-process without requiring heavy background JSON-RPC daemons, serving as a lean alternative to MCP servers.

Tier 03 · Community Bundles

Packages (pi install <pkg>)

Distributable bundles combining related Skills and Extensions into a single installable unit governed by a package.json manifest. Over 2,000 packages are indexed and shared across GitHub and community repositories.

Tier 04 · Orchestrator Subagent

Outer Delegation (delegate_task)

The integration pattern where parent cognitive harnesses (such as Waku Agent or OpenClaw) use their internal delegate_task tool to spawn Pi via CLI (pi -p), letting Pi execute the code-generation loop while the parent maintains system-wide memory and triage.

2. Step-by-Step Extensibility Flow Walkthrough

Tracing how capabilities escalate from markdown prompts to orchestrator subprocesses in Figure 4.0:

1

Tier 01: Skill Ingestion at Startup

When Pi boots, it scans .agent/skills/. If a skill like pokeapi.md is present, its markdown instructions are injected into the system prompt window to instruct the LLM on domain rules without altering the runtime.

2

Tier 02: TypeScript Tool Registration

If the task requires code execution beyond the 4 core tools, Pi dynamically loads scripts from ~/.pi/extensions/. It exposes typed functions (e.g. typeMatch(pokemon)) to the model's tool schema dictionary.

3

Tier 03: Package Installation & Scoping

Running pi install <package-name> clones community bundles into the user's extension directory, automatically wiring together skills, TypeScript tools, and documentation in a single step.

4

Tier 04: Outer Orchestrator Spawning

In multi-agent systems, Waku Agent evaluates user intent. Upon determining a coding requirement, Waku issues a delegate_task call that spawns pi -p "Implement PokéAPI client". Pi runs headlessly and streams finished code back to Waku.

3. Implementation Blueprint: Extension Loader & Orchestrator Delegation

Python harness illustrating how outer agents delegate coding tasks to Pi Agent via single-shot CLI:

waku_pi_delegation.py · Outer Orchestrator Delegation to Pi Agent
import subprocess
import os
import json
from typing import Dict, Any

class WakuAgentOrchestrator:
    """Outer orchestrator managing high-level planning and delegating coding to Pi."""
    def __init__(self, workspace_path: str):
        self.workspace_path = workspace_path

    def delegate_to_pi(self, task_description: str) -> Dict[str, Any]:
        """Spawns Pi Agent as a headless coding engine via Face 02 (pi -p)."""
        print(f"[WAKU ORCHESTRATOR] Delegating code generation to Pi Agent...")
        cmd = ["pi", "-p", task_description]

        # Execute Pi in subprocess
        try:
            result = subprocess.run(
                cmd,
                cwd=self.workspace_path,
                capture_output=True,
                text=True,
                check=True
            )
            return {
                "status": "success",
                "output": result.stdout.strip(),
                "exit_code": result.returncode
            }
        except subprocess.CalledProcessError as e:
            return {
                "status": "error",
                "stderr": e.stderr.strip(),
                "exit_code": e.returncode
            }

# Example custom extension structure (~/.pi/extensions/poke_tool.py)
class PokeExtension:
    """Demonstrating Tier 02 TypeScript/Python custom tool injection."""
    name = "type_match"
    description = "Checks Pokémon elemental type advantages."

    @staticmethod
    def execute(pokemon: str) -> str:
        types_db = {"pikachu": "electric", "psyduck": "water", "charizard": "fire"}
        p_type = types_db.get(pokemon.lower(), "normal")
        return f"{pokemon.capitalize()} is type [{p_type}]."

if __name__ == "__main__":
    orchestrator = WakuAgentOrchestrator(workspace_path=".")
    # Demonstrating Tier 04 delegation
    task = "Inspect pokemon.py, add Psyduck error handling, and run pytest."
    print(f"Task: {task}")
    print("Orchestrator ready. Invokes: pi -p ")
