01 / FOUNDATION
Start here

Chatbot ≠ agent ≠ worker.

These words are often mixed together. They should not be. The difference is primarily about responsibility, action, autonomy, and persistence.

01

Chatbot

An AI you talk to. It answers, then waits for the next message. Its default loop is conversational.

YOU → AI → YOU
02

Agent

An AI that can work through a task: plan, use tools, inspect results, and adjust its next step.

GOAL → PLAN → ACT → CHECK
03

Worker

Our name for an agent with a standing job: a clear responsibility, trigger, tools, limits, and reporting mechanism.

JOB → TRIGGER → EXECUTE → REPORT
The important shift is this: you are no longer designing a conversation. You are designing a system that receives a goal, acts within boundaries, and produces a useful result.
From Chatbot to Worker
Increasing capability means adding execution infrastructure.
02 / CORE VOCABULARY
The 12 terms

These become your daily vocabulary.

You do not need to memorize them. Interact with each card, follow the diagrams, and use the search box to connect terms together.

⌕
12 / 12 visible
01
Model
The trained AI engine that reads input and generates a response.
⌄
What it means

The trained AI engine that reads your request and produces a response.

Why it matters

Models differ in capability, reasoning quality, latency, cost, context capacity, and reliability.

Where it shows up

When you choose what the worker thinks with: GPT, Claude, Gemini, or another model provider.

MODEL = the “brain” that performs inference.
02
Prompt
The instruction and background supplied to the model.
⌄
What it means

The instruction, context, constraints, examples, and expected behavior given to a model.

Why it matters

A vague instruction produces ambiguous work. Clear prompts define the job, standards, and boundaries.

Where it shows up

“Summarize today’s inbox and flag anything that needs me.”

PROMPT = intent + instructions + constraints + useful context.
03
Output
The answer, draft, file, summary, or action produced by the system.
⌄
What it means

The tangible result produced by the worker: text, data, file, recommendation, or external action.

Why it matters

Judge the usefulness of the work, not just whether the conversation sounded intelligent.

Where it shows up

A daily brief, drafted reply, updated spreadsheet, generated file, or blocker report.

OUTPUT = the thing that actually moves the workflow forward.
04
Context
Everything the model can currently see while it works.
⌄
What it means

Your request, notes, examples, files, previous messages, retrieved data, and other information available to the model at that moment.

Why it matters

Context makes a worker specific to your situation instead of generic.

Where it shows up

Business notes, client rules, inbox examples, project briefs, documents, retrieved records.

CONTEXT = everything available to reason over right now.
05
Context window
The model's temporary workspace and its capacity limit.
⌄
What it means

The amount of text and data a model can process as context during an interaction.

Why it matters

Large inputs consume capacity. Long tasks may require careful context management or external memory.

Where it shows up

Huge documents, long chats, large tool responses, and many examples can push against the available window.

CONTEXT WINDOW = temporary workspace, not permanent memory.
06
Memory
Information saved between sessions so the worker does not start from zero.
⌄
What it means

Persistent information stored outside the temporary context, such as preferences, facts, recurring workflows, and business knowledge.

Why it matters

Persistent memory allows consistency across separate sessions.

Where it shows up

Preferred tone, company names, project rules, recurring tasks, and other durable facts.

MEMORY = selected information that survives the session.
07
Session
One continuous work thread from beginning to end.
⌄
What it means

A continuous interaction or execution thread where the agent retains relevant state and context.

Why it matters

Sessions keep work focused. Starting a fresh session for a different task can prevent unrelated context from contaminating decisions.

Where it shows up

Continuing a task, switching jobs, opening a new work thread, or resuming a running workflow.

SESSION ≠ MEMORY. A session is the work thread; memory can survive it.
08
Tool
A capability the worker can invoke to act on the world.
⌄
What it means

A function, integration, script, service, or API operation that lets the worker perform an external action.

Why it matters

Without tools, the model mainly talks. With tools, it can retrieve data, modify systems, send messages, and execute tasks.

Where it shows up

Email, calendar, browser, Drive, Sheets, databases, code execution, search, and custom APIs.

TOOL = a capability exposed to the worker.
09
Integration / API
The connection that lets software systems talk to each other.
⌄
What it means

An integration is the user-friendly connection; an API is the technical interface underneath it.

Why it matters

Workers become useful when they can reach real systems instead of relying entirely on pasted text.

Where it shows up

Gmail, Slack, Stripe, HubSpot, Google Drive, CRMs, internal APIs, and custom business systems.

API = a defined technical doorway into another system.
10
Trigger · Workflow · Automation
The start condition, execution sequence, and unattended operation.
⌄
What it means

A trigger starts the job. A workflow defines the steps. Automation means the job can run without manually initiating every step.

Why it matters

This is the mechanism for turning AI from a one-off helper into recurring operational infrastructure.

Where it shows up

Every morning, on a new email, when a database record changes, or when someone sends a command.

TRIGGER → WORKFLOW → AUTOMATION
11
Guardrail · Permission · Human approval
Rules that define what the worker can do alone and what requires a person.
⌄
What it means

Controls that limit data access, tools, actions, scope, and autonomy.

Why it matters

Autonomy without boundaries is not sophistication. It is uncontrolled blast radius.

Where it shows up

Draft before send, approve before payment, confirmation before deletion, refusal to reveal private data.

SAFE AUTONOMY = fast on reversible tasks + pause on irreversible tasks.
12
Logs · Tests · Iteration
The feedback system for making workers reliable.
⌄
What it means

Logs record execution. Tests verify behavior. Iteration improves the system based on evidence from actual runs.

Why it matters

Reliable systems emerge through measurement and refinement, not optimistic prompting.

Where it shows up

Reviewing output, identifying failures, tightening rules, adding examples, and running the workflow again.

RUN → LOG → TEST → FIND FAILURE → ITERATE → RUN AGAIN
“You don't need to memorize these today. You will use every one of them by the end of Module 2, and that is when they will stick.” THE POINT IS USAGE, NOT MEMORIZATION.
03 / MENTAL MODEL
Context vs memory

Temporary workspace is not long-term memory.

A worker can only reason over what is available to it. Context, the context window, session state, and persistent memory are related — but they are not interchangeable.

Context Architecture
What the model can see now vs what the system remembers later.
Context now ≠ Memory forever ≠ Session state
04 / AI BASICS
The model layer

Understand the machine before you orchestrate it.

These concepts explain what the model is doing, what can go wrong, and how a raw model becomes part of a useful agent system.

01
LLM

Large Language Model

A model trained on large amounts of data to understand and produce language. Some modern models also handle images, audio, code, and other modalities.

02
TK

Token

A small piece of text processed by the model. Tokens affect input size, output size, cost, and how much information can fit into a context window.

03
!

Hallucination

A model produces a false or unsupported statement with confidence. Important work therefore needs verification, constraints, or authoritative retrieval.

04
MP

Model provider

A company or service that gives developers access to models. Examples include OpenAI, Anthropic, Google, and other providers.

05
HITL

Human in the loop

A deliberate checkpoint where an agent pauses before a sensitive, consequential, or irreversible action such as send, pay, or delete.

06
ORCH

Orchestration

Coordination across models, agents, tools, and workflow steps. The orchestrator decides what should happen next and routes work accordingly.

07
+

Plugin

An add-on that extends an AI application or agent with additional capabilities, instructions, tools, or integrations.

08
↔

Connector

A bridge between an AI system and an external service or data source, commonly using APIs and OAuth to control access.

09
BI

AI / Model Bias

A systematic tendency that can create distorted, unbalanced, or unfair outcomes. Bias can come from data, model design, human choices, or system use.

10
AF

Agent Framework

A toolkit for managing agent tools, workflows, memory, decisions, execution loops, and interactions. LangChain and LangGraph are examples.

11
RAG

Retrieval-Augmented Generation

Retrieve relevant external information first, then provide it as context so the model can generate an answer grounded in that information.

12
≡

AI Agent Harness

The infrastructure around the model: tools, loops, execution environment, memory, state handling, and safety controls.

Agent = Model + Harness

Model = intelligence · Harness = tools + execution + memory + state + guardrails

06 / SECURITY
Secrets and permissions

Autonomy without security is a liability.

An agent that can read and write real systems becomes part of your security boundary. Treat credentials, file access, and external instructions accordingly.

01 / IDENTITY

SSH + SSH key

SSH is a secure remote access method. An SSH key is a cryptographic credential used to authenticate you without relying on a plain password.

02 / NETWORK

Firewall

A firewall controls which network connections can reach a machine. Expose only the services that actually need to be reachable.

03 / FILES

Permissions

File permissions define who can read, modify, or execute files. Least privilege reduces blast radius.

04 / RECOVERY

Backup

A backup is a separate saved copy that allows recovery from deletion, corruption, accidents, or infrastructure failure.

!
Critical rule: secrets are not configuration trivia.

API keys, passwords, access tokens, SSH private keys, and other credentials are secrets. Treat an API key like a password.

Secret handling architecture
Keep credentials outside source code and restrict who can access them.
ENV
$

Environment variable

A named value exposed to software through the environment. Frequently used to provide configuration and credentials without placing them in code.

KEY
K

API key

A credential that lets software authenticate to a service. Protect it as a secret and avoid committing it to source control.

SECRET
S

Secret

Any credential that should not be publicly exposed: passwords, API keys, access tokens, private keys, and similar values.

INJECTION
↯

Prompt injection

Malicious or misleading instructions embedded inside content the worker reads. Safe systems treat external content as data, not automatically as authority.

Prompt injection: data vs instructions
The worker should distinguish trusted instructions from untrusted content.
07 / FILES + VERSIONS
The worker needs structure

Organized files become part of the system.

Version control and predictable file structures make agent systems easier to inspect, reproduce, debug, and evolve.

A simple worker project tree
The exact structure can vary. The principle is predictable organization.
GIT
G

Git

A version control system that tracks changes to files over time. It gives you history, comparison, rollback, and collaboration.

COMMIT
C

Commit

A saved snapshot of a project's tracked changes in Git. A credential accidentally committed to history can remain exposed even after deletion.

MD
#

Markdown

A lightweight text format useful for notes, specifications, system instructions, documentation, skills, and agent knowledge files.

TREE
/

File tree

The folder structure the worker uses. Predictable organization makes information easier for both humans and agents to locate.

08 / THE BRAIN
Externalized knowledge

Your worker needs a business brain.

A model does not automatically know your company, your preferred workflows, your internal rules, or your operating style. Those need to exist somewhere accessible.

Brain architecture
Plain-text knowledge + reusable skills + project rules.
APP
O

Obsidian

A notes application that stores knowledge as plain text files. It can function as a lightweight business brain for an agent.

VAULT
V

Vault

Obsidian's term for a folder containing its notes and related files.

BRAIN
B

Brain

A structured set of notes describing your business, projects, preferences, policies, and operating rules.

SKILL
SK

Skill

A reusable instruction set for performing a specific task consistently.

09 / CONNECTIONS
Reach the outside world

The worker becomes useful when it can connect.

Gateways, MCP, connector platforms, APIs, and tools all solve versions of the same underlying problem: getting controlled access to external capabilities.

Gateway → Worker → MCP / Connectors → Services
One way to visualize the connection layer.
01
GW

Gateway

A channel through which a user interacts with the worker: Telegram, Slack, web chat, email, or another interface.

02
M

MCP

Model Context Protocol: a standard pattern for connecting AI systems with tools and data instead of inventing a custom interface for every integration.

03
CP

Connector Platform

A prebuilt connection layer for external services. These platforms can reduce integration work by standardizing authentication and actions.
