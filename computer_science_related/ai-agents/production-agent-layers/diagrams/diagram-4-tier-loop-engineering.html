The 4-Tier Loop Hierarchy & 3-Speed Feedback

Loop engineering defines what happens when an attempt fails: from micro task execution and evaluator verifiers to multi-run hill climbing and Andrew Ng's 3-speed product feedback cycles.

Detailed Architectural Explanations

Loop 02 · Evaluator Grader

Where Design Patterns Live

Popular agent patterns (Critic-Actor, Self-Healing Code, Human-in-the-Loop approval) all reside inside Loop 2. In our insurance claim graph, after the damage assessment node runs, an evaluation node grades the evidence. If confidence is below 80%, Loop 2 forces a retry with specific feedback before payout routing.

Andrew Ng's 3 Speeds

Fast vs. Middle vs. Slow Loops

Building 0-to-1 AI products requires coordinating three distinct time scales: Fast Loops (minutes: LLM writing and running code in terminal), Middle Loops (hours: developers reviewing prototypes and revising specs), and Slow Loops (weeks: analyzing aggregated production telemetry to steer product direction).

1. Loop Hierarchy & 3-Speed Definitions

Rigorous technical definitions for each tier in Figure 2.0:

Tier 01 · Immediate Action

Loop 01 · Task Execution (ReAct)

The fundamental sub-second loop cycling between reasoning, tool invocation, and observation parsing. Confined to a single isolated agent attempt with no structural evaluation of final task success.

Tier 02 · Design Patterns

Loop 02 · Verifier & Grader Loop

The focal layer where agent design patterns (Critic-Actor, Self-Healing Code, Reflection, and HITL) operate. An independent evaluator grades outputs; if validation fails, it generates structured feedback and resets Loop 1 up to $N$ retry attempts.

Tier 03 · Asynchronous State

Loop 03 · Event-Driven Agent Loop

Governs long-running workflows that pause and sleep. Re-awakens via webhooks, Kafka messages, or Pub/Sub queues when external human actions occur (e.g. claimant uploads supplemental repair receipts).

Tier 04 · Continuous Optimization

Loop 04 · Hill-Climbing Meta Loop

Operates offline across hundreds of historical runs. Aggregates failure logs, runs LLM-as-a-judge evals, and automatically mutates system prompt instructions and confidence thresholds to maximize global accuracy over weeks.

Speed 01 · Minutes

Fast Loop (Agentic Coding)

The 1-5 minute development cycle where autonomous coding agents (e.g. Pi Agent, Claude Code) generate code, run automated tests, inspect error stacks, and iteratively repair syntax before developer review.

Speed 02 & 03 · Product Cycles

Middle & Slow Feedback Loops

Middle Loop (1-12 hours): Developers and stakeholders review working prototypes and adjust specifications. Slow Loop (1-4 weeks): Ingestion of production telemetry, user churn, and A/B test data to redefine system roadmaps.

2. Step-by-Step Loop Flow Walkthrough

Tracing the escalation and nesting of feedback mechanisms in Figure 2.0:

1

Loop 1: Task Execution Phase

The agent executes a ReAct turn, querying APIs or running Computer Vision models to produce a candidate outcome (e.g., initial scratch repair estimate of $4,500).

2

Loop 2: Verifier / Critic Gate & Self-Healing

The Evaluator Grader intercepts the output. Detecting that a bumper scratch does not warrant $4,500, it rejects the candidate and issues actionable critique back to the agent: "Re-evaluate with localized bumper paint formulas". Loop 1 re-executes cleanly.

3

Loop 3: Webhook Wait & Event Re-awakening

If the claim requires supplemental documentation, the graph persists checkpoint state and goes dormant. Days later, a webhook fires upon document upload, re-hydrating the execution state.

4

Loop 4: Batch Benchmark Hill-Climbing

At the end of the week, 10,000 processed claims are evaluated in batch. Prompt optimizers adjust system prompt directives to prevent bumper cost hallucinations globally.

5

Connecting to Andrew Ng's 3 Speeds

Fast Loops empower the engineering team to build tools in minutes. Middle Loops validate prototype UX in hours. Slow Loops ensure production claims match business margin goals over weeks.

3. Implementation Blueprint: Nested Loop Hierarchy

Python harness illustrating nested Loop 1 (ReAct execution) governed by Loop 2 (evaluator grading with reflection):

nested_loops_engine.py · Loop 1 & Loop 2 Nested Feedback Implementation
import time
from typing import Dict, Any, Tuple, Optional

class LoopEngine:
    def __init__(self, max_l2_retries: int = 3):
        self.max_l2_retries = max_l2_retries

    # LOOP 01: ReAct Task Execution (Sub-second)
    def loop_1_react_step(self, task: str, critique: Optional[str] = None) -> Dict[str, Any]:
        """Performs single model call and tool execution with optional feedback."""
        if critique:
            # Self-healing path: model adjusted based on evaluator feedback
            return {"action": "paint_buffing", "cost": 300.0, "confidence": 0.95}
        else:
            # Uncalibrated first attempt: hallucinates bumper replacement
            return {"action": "bumper_replacement", "cost": 4500.0, "confidence": 0.65}

    # LOOP 02: Verifier & Grader (Critic-Actor Pattern)
    def loop_2_verifier_gate(self, output: Dict[str, Any], task_context: str) -> Tuple[bool, Optional[str]]:
        """Grades output against policy and sanity constraints."""
        if "minor scratch" in task_context.lower() and output["cost"] > 1000.0:
            feedback = f"Cost ${output['cost']} exceeds realistic limits for minor scratch."
            return False, feedback
        if output["confidence"] < 0.85:
            return False, "Confidence score below threshold (85%)."
        return True, None

    # THE NESTED EXECUTION CYCLE
    def execute_with_loops(self, task: str) -> Dict[str, Any]:
        critique = None
        for attempt in range(1, self.max_l2_retries + 1):
            # Loop 1 execution
            candidate = self.loop_1_react_step(task, critique)
            
            # Loop 2 evaluation
            passed, feedback = self.loop_2_verifier_gate(candidate, task)
            print(f"[Loop 2 Attempt {attempt}] Passed: {passed} | Output: {candidate}")

            if passed:
                return {"status": "SUCCESS", "result": candidate, "attempts": attempt}
            
            critique = feedback  # Pass critique into next Loop 1 turn

        # If Loop 2 retries exhausted -> Escalate to Human
        return {"status": "ESCALATE_TO_HUMAN", "last_candidate": candidate}

if __name__ == "__main__":
    engine = LoopEngine(max_l2_retries=3)
    task_input = "Evaluate insurance damage for minor scratch on right door panel."
    result = engine.execute_with_loops(task_input)
    print("Final Result:", result)
    assert result["status"] == "SUCCESS"
    assert result["result"]["cost"] == 300.0
