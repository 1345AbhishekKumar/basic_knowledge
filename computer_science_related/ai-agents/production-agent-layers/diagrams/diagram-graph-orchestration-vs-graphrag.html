Graph Orchestration vs. Graph Knowledge & Memory

Understanding the two distinct dimensions of Graph Engineering: multi-agent execution DAGs (LangGraph Insurance Claim System) versus relational knowledge retrieval (GraphRAG, HippoRAG 2, and Temporal Memory).

FIGURE 3.0 — GRAPH ORCHESTRATION (EXECUTION) VS. GRAPH KNOWLEDGE & MEMORY (GRAPHRAG)

Detailed Architectural Explanations

Graph for Orchestration

The 5-Agent Insurance Claim DAG

Graph orchestration models the deterministic workflow of specialized agents: Intake Agent normalizes data, Damage Evidence Agent runs CV analysis, Evaluate Loop retries or escalates, Policy & Risk Agent verifies legal thresholds, and Payout Router issues the final approval or rejection.

Graph for Knowledge

GraphRAG & Temporal Memory

Unlike static vector search, GraphRAG extracts entity relationships and clusters them into community summaries, allowing the system to perform multi-hop reasoning (e.g. connecting a driver's prior claims across three different regional subsidiaries).

1. Graph Orchestration & Knowledge Definitions

Rigorous technical definitions for both graph dimensions illustrated in Figure 3.0:

Orchestration Graph

Execution DAG (LangGraph Workflow)

A state machine graph where nodes represent specialized agents or functions (Intake, Damage CV, Policy Risk, Payout) and edges represent conditional transitions based on validated state payloads. Guarantees deterministic business flow execution.

Conditional Gate

Evaluate Damage Loop

The focal verification node inside the execution DAG. Intercepts computer vision findings, scores confidence, and dynamically routes: loop back with corrective critique (up to 20 retries), advance to Policy & Risk, or abort to Human Review.

Knowledge Graph

GraphRAG & HippoRAG 2

Knowledge retrieval architecture that extracts entities and predicates into an interconnected graph. Leverages Leiden community detection algorithms to generate hierarchical summaries that answer broad, high-level questions.

Relational Retrieval

Multi-Hop Traversal

Navigating across linked entity nodes to discover indirect connections (e.g. Claimant → Owns Vehicle → Insured by Policy B → Involved in Prior Claim with Subsidiary C) that naive semantic vector search fails to retrieve.

Memory Modeling

Temporal Knowledge Graphs

Attaching timestamp metadata (valid_from, valid_until) to graph relationships. Essential for tracking policy revisions, driver license suspensions, and historical claim sequences over multi-year horizons.

Engineering Tradeoff

When Graph Wins vs Vector Lookup

Graph Wins: When queries require multi-hop relationship joins or temporal chronology. Vector Wins: Direct factual lookups (cheaper, faster). Critical risk: Inaccurate entity resolution creates spurious edges that corrupt downstream answers.

2. Step-by-Step Execution & Retrieval Walkthrough

Tracing the flow through the Execution DAG (left) and the Knowledge Retrieval Graph (right) in Figure 3.0:

1

Node 1: Intake Normalization & Validation

The Intake Agent ingests raw claim data, sanitizes inputs, validates policy numbers, and commits the initial state snapshot to the orchestration graph.

2

Node 2 & 3: Damage Assessment & Evaluate Loop

The Damage Evidence Agent runs computer vision tools. The Evaluate Damage Loop inspects the output. If confidence is low or cost conflicts with visual scratch depth, it triggers a self-healing retry loop or flags for human inspection.

3

Node 4: Policy & Risk with GraphRAG Query

The Policy & Risk Agent triggers a GraphRAG multi-hop query into the corporate knowledge graph, traversing past claims, policy exclusion clauses, and linked regional database nodes to calculate a unified risk score.

4

Node 5: Payout Recommendation & Routing Gateway

The final node examines risk score and estimated repair costs, branching to Auto-Approve (low risk, sub-limit), Reject (policy exclusion), or Human-in-the-Loop review.

3. Implementation Blueprint: LangGraph Orchestration & Multi-Hop Traversal

Python harness illustrating the separation between stateful execution DAGs and relational knowledge lookups:

graph_orchestration_vs_rag.py · Execution DAG & GraphRAG Traversal Blueprint
from typing import Dict, List, Any, Optional

# ==========================================
# 1. GRAPH FOR KNOWLEDGE (GRAPHRAG ENTITY STORE)
# ==========================================
class KnowledgeGraphRAG:
    """Simulates entity extraction and multi-hop relationship traversal."""
    def __init__(self):
        # Triplet graph: (subject, predicate, object)
        self.edges = [
            ("driver_john_doe", "owns_vehicle", "vin_12345"),
            ("vin_12345", "covered_by", "policy_silver"),
            ("policy_silver", "has_exclusion", "flood_damage"),
            ("driver_john_doe", "filed_claim_in_2024", "subsidiary_north"),
            ("subsidiary_north", "flagged_status", "prior_dispute")
        ]

    def multi_hop_search(self, start_entity: str) -> List[str]:
        """Finds secondary connections 2 hops away from the root entity."""
        first_hop = [obj for subj, pred, obj in self.edges if subj == start_entity]
        second_hop = []
        for entity in first_hop:
            second_hop.extend([f"{entity} -> {pred} -> {obj}" for subj, pred, obj in self.edges if subj == entity])
        return second_hop

# ==========================================
# 2. GRAPH FOR ORCHESTRATION (EXECUTION DAG)
# ==========================================
class ClaimState:
    def __init__(self, driver: str, incident: str, estimated_damage: float):
        self.driver = driver
        self.incident = incident
        self.estimated_damage = estimated_damage
        self.risk_flags: List[str] = []
        self.decision: Optional[str] = None

class InsuranceClaimDAG:
    def __init__(self, knowledge_rag: KnowledgeGraphRAG):
        self.rag = knowledge_rag

    def intake_node(self, state: ClaimState) -> None:
        print(f"[Node 1: Intake] Processing claim for {state.driver}...")

    def damage_evidence_node(self, state: ClaimState) -> None:
        print(f"[Node 2: Damage] Calculating repair estimate: ${state.estimated_damage}")

    def evaluate_loop_gate(self, state: ClaimState) -> bool:
        """Evaluator Grader Node: loops if invalid."""
        if state.estimated_damage > 10000.0:
            print("[Node 3: Evaluate] Warning: Excessive damage estimate.")
            return False
        return True

    def policy_risk_node(self, state: ClaimState) -> None:
        print("[Node 4: Policy & Risk] Querying GraphRAG knowledge graph...")
        traversal_results = self.rag.multi_hop_search(state.driver)
        for rel in traversal_results:
            if "prior_dispute" in rel:
                state.risk_flags.append("PRIOR_REGIONAL_DISPUTE_FOUND")

    def payout_router_node(self, state: ClaimState) -> str:
        if state.risk_flags:
            state.decision = "ROUTE_HUMAN_INVESTIGATOR"
        else:
            state.decision = f"AUTO_APPROVE_${state.estimated_damage}"
        return state.decision

    def execute(self, state: ClaimState) -> str:
        self.intake_node(state)
        self.damage_evidence_node(state)
        if not self.evaluate_loop_gate(state):
            return "ESCALATE_SPECIAL_INVESTIGATION"
        self.policy_risk_node(state)
        return self.payout_router_node(state)

if __name__ == "__main__":
    kg = KnowledgeGraphRAG()
    dag = InsuranceClaimDAG(kg)

    claim_state = ClaimState(driver="driver_john_doe", incident="Fender bender", estimated_damage=850.0)
    final_decision = dag.execute(claim_state)
    print(f"Workflow Decision: {final_decision} (Risk Flags: {claim_state.risk_flags})")
