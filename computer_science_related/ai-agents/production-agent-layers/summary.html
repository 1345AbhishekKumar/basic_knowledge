Executive Summary & Core Philosophy

The 6 Engineering Layers of Production AI Agents

Bridging the gap between fragile prototypes and production systems: how Maryam architected a 5-agent insurance claim pipeline using 4-tier feedback loops, Graph Orchestration, GraphRAG, and 72 automated evals.

1. The Production Gap

In a classic enterprise failure scenario, a multi-agent system runs end-to-end, all graph nodes complete successfully, and the system approves a $4,500 payout for a minor scratch.

Why did it fail? Because structure alone does not ensure reliability. Moving from prompt demos to mission-critical systems requires climbing six distinct, progressive engineering layers.

"Design patterns tell you what local feedback mechanism to use. Loop engineering tells you how feedback works across the whole agentic system."

— Production Agent Engineering Principles

2. The 6 Progressive Engineering Layers

Layer 01 & 02

Prompt & Context Engineering

One-shot constraints and context budget allocation. Preventing context rot beyond the 10% ChromaDB threshold using offloading and compaction.

Layer 03 & 04

Execution & Loop Engineering

ReAct task execution plus cross-cutting feedback hierarchies (Task → Verifier/Grader → Event-Driven → Multi-Run Hill Climbing).

Layer 05 & 06 · Production

Graph, Harness & 72 Evals

LangGraph execution DAGs + GraphRAG paired with runtime governors, circuit breakers, and 72 automated regression unit evals.

Core Architectural Principles

  • Use Graphs for Orchestration Always, for Knowledge Selectively: LangGraph controls deterministic multi-agent state flows, while GraphRAG is reserved for multi-hop, temporally sensitive document retrieval.
  • Andrew Ng's 3-Speed Product Feedback: Iterate at minutes (agentic coding), hours (developer prototype review), and weeks (production telemetry).
  • Zero Regressions via 72 Automated Evals: Continuous testing across damage evidence, policy limits, fraud triggers, and immutable audit logs.

4. Definitions of the 6 Engineering Layers

Moving beyond fragile AI demos requires mastering the technical boundaries of each progressive engineering layer:

Layer 01 · Foundation

Prompt Engineering

The baseline craft of structuring one-shot instructions: role, task specification, few-shot exemplars, negative constraints, and output schema specifications. Assumes a single, stateless request-response interaction with zero feedback or dynamic tooling.

Layer 02 · Memory & Attention

Context Engineering & Context Rot

The algorithmic management of context window budgets. Addresses context rot (empirically measured as >10% retrieval quality degradation in standard vector databases like ChromaDB over long sessions) through memory offloading, semantic compaction, and dynamic tool schema injection (Tool RAG).

Layer 03 · Autonomous Action

Agent Execution Engineering

The execution of autonomous tool-calling cycles using the ReAct (Reason → Act → Observe) pattern. Focuses on input sanitization, deterministic parameter extraction, error recovery, and confidence scoring for a single isolated agent attempt.

Layer 04 · Cross-Cutting Control

Loop Engineering

The systemic feedback engine governing what happens when an attempt fails. Spans 4 nested tiers: Loop 1 (sub-second ReAct task execution), Loop 2 (evaluator/critic grading with automatic retry), Loop 3 (event-driven webhook re-awakening), and Loop 4 (batch hill-climbing optimization across historical runs).

Layer 05 · Topology

Graph Engineering (Orchestration vs Knowledge)

Bifurcated into two distinct domains: Graph Orchestration (LangGraph state machines directing deterministic agent execution DAGs) and Graph Knowledge (GraphRAG / HippoRAG 2 performing multi-hop entity traversal and temporal relationship resolution across documents).

Layer 06 · Production SLA

Harness Engineering & 72 Production Evals

The production runtime wrapper enforcing pre-flight input validation, circuit breakers against infinite execution loops, token budget caps, immutable audit logging, and a 72-eval test matrix covering damage evidence, policy rules, fraud anomalies, and payout boundaries.

5. Step-by-Step Enterprise Insurance Pipeline Walkthrough

Tracing Maryam's 5-agent insurance claim pipeline through the 6 engineering layers to demonstrate how production reliability is enforced:

1

Pre-Flight Gateway & Intake Normalization (Layers 1 & 6)

The user submits an insurance claim with accident photos and narrative. Layer 6 Harness sanitizes file inputs and authenticates policy tokens. The Intake Agent normalizes metadata and extracts vehicle VIN, damage claims, and incident timestamps.

2

Computer Vision Damage Evidence Extraction (Layers 2 & 3)

The Damage Evidence Agent analyzes submitted photos using vision models. Tool RAG ensures only relevant vehicle part schemas are loaded into the prompt, preventing context rot. The agent produces a localized repair cost estimate.

3

Loop 2 Verifier / Critic Grading (Layer 4)

An independent Evaluator Grader node inspects the damage assessment. If photo evidence shows only a minor bumper scratch but the repair estimate is $4,500, Loop 2 rejects the output with explicit feedback: "Repair estimate inconsistent with visual scratch depth", triggering up to 20 self-healing retries before escalating to human adjusters.

4

GraphRAG Multi-Hop Policy & Fraud Check (Layer 5)

The Policy & Risk Agent traverses an internal GraphRAG knowledge graph to cross-reference the claimant's policy terms, deductible thresholds, and historical claims filed across regional subsidiaries, assigning an objective fraud risk score.

5

Payout Routing & Post-Flight Audit Logging (Layer 6)

The Payout Router checks calculated amounts against hard limits. If risk is low and cost is under threshold, it emits auto-approval; otherwise, it routes to Human-in-the-Loop (HITL). Layer 6 writes an immutable audit record to the corporate datastore.

6. Implementation Blueprint: 6-Layer Multi-Agent Claim Harness

Python implementation illustrating the interaction between LangGraph state routing, Loop 2 evaluator grading, and automated eval verification:

production_claim_pipeline.py · 6-Layer Architecture with Loop 2 Grader
import os
import json
from typing import Dict, Any, List, Optional

# ==========================================
# LAYER 6: HARNESS RUNTIME GOVERNOR & EVALS
# ==========================================
class HarnessGovernor:
    """Enforces pre-flight checks, token caps, and audit logs."""
    def __init__(self, max_payout_limit: float = 2500.0, max_retries: int = 3):
        self.max_payout_limit = max_payout_limit
        self.max_retries = max_retries
        self.audit_trail: List[Dict[str, Any]] = []

    def pre_flight_validate(self, claim: Dict[str, Any]) -> bool:
        required = ["claim_id", "policy_id", "description", "claimed_amount"]
        return all(k in claim for k in required)

    def log_audit(self, stage: str, data: Dict[str, Any]) -> None:
        self.audit_trail.append({"stage": stage, "payload": data})

# ==========================================
# LAYER 4 & 5: GRAPH ORCHESTRATION & LOOP 2 GRADER
# ==========================================
class ClaimState:
    def __init__(self, claim_data: Dict[str, Any]):
        self.claim_data = claim_data
        self.estimated_damage: float = 0.0
        self.confidence_score: float = 0.0
        self.risk_score: float = 0.0
        self.eval_feedback: Optional[str] = None
        self.decision: Optional[str] = None

class ProductionClaimPipeline:
    def __init__(self, governor: HarnessGovernor):
        self.governor = governor

    # Stage 1: Intake Normalization
    def intake_node(self, state: ClaimState) -> None:
        self.governor.log_audit("intake", {"claim_id": state.claim_data["claim_id"]})

    # Stage 2: Damage Evidence Agent (Computer Vision assessment simulation)
    def damage_evidence_node(self, state: ClaimState, attempt: int) -> None:
        # If attempting after feedback, refine assessment
        if state.eval_feedback:
            state.estimated_damage = 350.0  # Corrected scratch repair cost
            state.confidence_score = 0.94
        else:
            # Flawed initial estimate (the $4,500 bumper scratch failure mode)
            state.estimated_damage = state.claim_data["claimed_amount"]
            state.confidence_score = 0.62

    # Stage 3: Loop 2 Verifier / Critic Grader
    def evaluator_grader_node(self, state: ClaimState) -> bool:
        """Loop 2 Critic: Evaluates claim consistency and confidence."""
        desc = state.claim_data["description"].lower()
        if "minor scratch" in desc and state.estimated_damage > 1000.0:
            state.eval_feedback = f"Discrepancy: '{desc}' cannot justify ${state.estimated_damage} payout."
            return False  # Failed evaluation -> trigger retry loop
        if state.confidence_score < 0.80:
            state.eval_feedback = "Confidence score below 80% SLA threshold."
            return False
        state.eval_feedback = None
        return True  # Passed evaluation

    # Stage 4: Policy & Risk Agent (GraphRAG cross-referencing simulation)
    def policy_risk_node(self, state: ClaimState) -> None:
        # Mock GraphRAG temporal relationship check
        state.risk_score = 0.15  # Low fraud risk

    # Stage 5: Payout Recommendation & Routing
    def payout_router_node(self, state: ClaimState) -> str:
        if state.risk_score > 0.70:
            state.decision = "ESCALATE_FRAUD_INVESTIGATION"
        elif state.estimated_damage > self.governor.max_payout_limit:
            state.decision = "ROUTE_HUMAN_IN_THE_LOOP"
        else:
            state.decision = f"AUTO_APPROVE_PAYOUT_${state.estimated_damage:.2f}"
        self.governor.log_audit("payout_decision", {"decision": state.decision})
        return state.decision

    # Graph Execution Loop
    def execute(self, claim_data: Dict[str, Any]) -> Dict[str, Any]:
        if not self.governor.pre_flight_validate(claim_data):
            return {"status": "REJECTED_PREFLIGHT"}

        state = ClaimState(claim_data)
        self.intake_node(state)

        # Loop 2 Self-Healing Cycle
        for attempt in range(1, self.governor.max_retries + 1):
            self.damage_evidence_node(state, attempt)
            passed = self.evaluator_grader_node(state)
            if passed:
                break

        if state.eval_feedback is not None:
            state.decision = "ROUTE_HUMAN_REVIEW_UNRESOLVED_DISCREPANCY"
            return {"status": state.decision, "audit": self.governor.audit_trail}

        self.policy_risk_node(state)
        decision = self.payout_router_node(state)
        return {"status": decision, "damage": state.estimated_damage, "audit": self.governor.audit_trail}

# ==========================================
# 72-EVAL SUITE VERIFICATION (SAMPLE UNIT EVAL)
# ==========================================
def test_minor_scratch_rejection_eval():
    governor = HarnessGovernor()
    pipeline = ProductionClaimPipeline(governor)
    
    # Test case: Claiming $4,500 on a minor scratch
    test_claim = {
        "claim_id": "CLM-9021",
        "policy_id": "POL-8842",
        "description": "Minor scratch on front passenger bumper",
        "claimed_amount": 4500.0
    }
    
    result = pipeline.execute(test_claim)
    # Verify that Loop 2 caught the discrepancy and corrected the payout
    assert result["status"] == "AUTO_APPROVE_PAYOUT_$350.00"
    print("Eval test_minor_scratch_rejection_eval PASSED.")

if __name__ == "__main__":
    test_minor_scratch_rejection_eval()
