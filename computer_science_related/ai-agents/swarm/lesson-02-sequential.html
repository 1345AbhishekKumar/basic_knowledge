Lesson 02 · Sequential Workflow · Chain of Handoffs

Sequential agents: research → analysis → report

Research agent gathers, Analysis processes, Report writes. A classic assembly line — easy to reason about, but everything waits for the previous step. Sean’s bridge before introducing parallelism.

How It Works

  • User asks → Research agent searches internet for context
  • Research passes findings → Analysis agent processes / scores
  • Analysis → Report agent writes polished report
  • Think: daily workflow — sequential handoffs you already know

Pros

  • Clear responsibility per stage — easy to debug
  • Quality compounds: analysis improves on real research
  • Simple to define — no orchestration layer
  • Deterministic order — reproducible

Why We Leave It

  • Wall-clock = sum of all stages — slow
  • Only one agent active at a time — wasteful
  • Cannot increase throughput without parallelism
  • Sean: “That's why agent teams comes really handy”
Explanation — the cost of order

Sequential = quality through handoff, time as the sum

Transcript: “After the user asks the first question, they can send that to a research agent first and it's going to pass down the context… to the analysis agent… then call a report agent.” Sean frames this as “a sequential workflow that would happen in a lot of daily life.” The diagram makes the handoff explicit: each agent receives prior output as context. That is why the arrows are labeled CONTEXT and INSIGHTS — they are not just control, they are data.

Why the three boxes are drawn equal width but the last is coral

Research, Analysis, Report each use the same white fill + ink stroke — none is focal until the report. Only Report is coral because it is the only artifact the user sees. The bar at the bottom translates wall-clock: research 280 + analysis 260 + report 220 = sequential time. No segment can reuse time from another; there is exactly one active agent at any moment.

What Sean wants you to feel before L03

  • Atomic benefit: specialization — research can be tuned for recall, analysis for scoring, report for prose. No single prompt has to do all three.
  • Atomic cost: additive latency and single-threaded capacity. The context that “passes down” also means the second agent cannot start before the first finishes.
  • Bridge line: “One problem with sequential agents is that they're doing things one by one… So that's why agent teams comes really handy.” — at 01:12 in the transcript.

Keep sequential when…

  • Order is correctness — analysis must see real research before it can score
  • Audit trail matters — you can point to which agent introduced which fact
  • Throughput is not the bottleneck

Leave it when…

  • Three lookups could run in parallel on different lenses (dev tools vs Spanish market)
  • One slow agent blocks four fast ones — head-of-line blocking
  • You need breadth of opinions, not depth of one chain

Quick math

If research takes 4s, analysis 3s, report 3s, sequential = 10s. Teams/swarm on five parallel scouts with same 4s research = ~4s + 1s synthesis = 5s. Same tokens, half the wait — but only if the work can be partitioned without passing context.

Core Concept Definitions — Sequential Agent Pipelines

Key Components & Systemic Constraints

The sequential pattern replaces the generalist single-agent loop with an assembly line of specialized stages. Specialization drastically improves output quality, but creates structural latency and throughput ceilings.

Context Pass-down Bar State Buffer

The top systemic boundary (CONTEXT PASSES DOWN — EACH AGENT RECEIVES PRIOR OUTPUT). Signifies state serialization where each downstream agent's prompt context is strictly composed of the predecessor's output artifacts.

Research Agent Stage 01

First assembly worker (search · scrape · gather). Tuned for broad web retrieval and raw data acquisition. Emits unformatted factual dumps without attempting to score or synthesize final recommendations.

Analysis Agent Stage 02

Second assembly worker (process · compare · score). Consumes raw research context, executes structured feature comparisons, eliminates duplicates, filters hallucinations, and extracts prioritized insights.

Report Agent Stage 03 · Deliverable

Final assembly worker (write · polish · deliver, styled in coral). Dedicated entirely to communication: consumes distilled insights and produces clean, formatted, client-ready markdown or PDF documents.

Additive Wall-Clock Latency System Constraint

Total response latency is strictly additive: \(T_{\text{total}} = T_{\text{research}} + T_{\text{analysis}} + T_{\text{report}}\). As shown on the timeline bar, each block must reach terminal completion before the next block can initialize.

Head-of-Line Blocking Failure Mode

Because capacity is strictly single-threaded (1 active agent at any instant), a slow, stuck, or rate-limited upstream agent blocks all downstream work, rendering the entire organization idle.

Flow Walkthrough

Step-by-Step Diagram Flow Walkthrough

1
User Prompt Ingress (QUESTION)

The user submits “Who is the best…” via arrow QUESTION into the Research Agent. Unlike single-agent loops, the user expects deep analysis rather than an immediate surface-level answer.

2
Research Stage Execution

The Research Agent searches web indices, scrapes candidate pages, and compiles a comprehensive body of raw context. During this phase (e.g., 4s / 280 units of time), both Analysis and Report agents sit completely idle.

3
Context Serialization & Handoff (CONTEXT)

The Research Agent serializes its findings and passes them over the solid muted arrow (CONTEXT) into the input context window of the Analysis Agent.

4
Analysis Stage Execution

The Analysis Agent processes the ingested facts, evaluates candidate credibility, scores comparative metrics, and extracts key differentiators. During this phase (3s / 260 units), Research has ended and Report waits.

5
Insights Handoff (INSIGHTS — Coral Accent)

The distilled analysis is handed off via the coral arrow (INSIGHTS) to the Report Agent. This marks the transition from information processing to client-facing synthesis.

6
Deliverable Generation & User Delivery (REPORT — Dashed Blue)

The Report Agent formats the document and routes it back via dashed link-blue arrow (REPORT) to the user as a complete, multi-stage deliverable.

Implementation Blueprint

Python Implementation: Sequential Specialist Pipeline

Runnable Python module illustrating typed state contracts, stage handoffs, and additive wall-clock accounting:

sequential_pipeline.py Python 3.11+ · Typed Handoff Chain 
import time
from dataclasses import dataclass
from typing import List, Dict, Any

@dataclass
class ResearchContext:
    query: str
    raw_sources: List[str]
    retrieved_facts: List[Dict[str, str]]

@dataclass
class AnalysisInsights:
    candidate_scores: Dict[str, float]
    differentiators: List[str]
    summary_verdict: str

@dataclass
class FinalReport:
    title: str
    executive_summary: str
    scored_breakdown: Dict[str, float]
    wall_clock_time: float

class SequentialPipeline:
    """Three-stage sequential assembly line: Research -> Analysis -> Report."""
    
    def stage_1_research(self, prompt: str) -> ResearchContext:
        print("[Stage 1: Research Agent] Scraping web & gathering context...")
        time.sleep(0.4) # Simulated latency
        return ResearchContext(
            query=prompt,
            raw_sources=["https://youtube.com/@seanstories", "https://news.ycombinator.com/item?id=38192"],
            retrieved_facts=[
                {"candidate": "Sean", "focus": "Hands-on AI agents & production workflows", "reputation": "high"},
                {"candidate": "Competitor B", "focus": "Theoretical ML tutorials", "reputation": "medium"}
            ]
        )

    def stage_2_analysis(self, context: ResearchContext) -> AnalysisInsights:
        print("[Stage 2: Analysis Agent] Scoring candidates and validating claims...")
        time.sleep(0.3) # Simulated latency
        scores = {}
        for fact in context.retrieved_facts:
            score = 9.4 if fact["reputation"] == "high" else 7.1
            scores[fact["candidate"]] = score
            
        return AnalysisInsights(
            candidate_scores=scores,
            differentiators=["Real-world agent orchestration code", "Evaluations of Kimi vs Claude"],
            summary_verdict="Sean holds strongest practical builder credibility in agent workflows."
        )

    def stage_3_report(self, insights: AnalysisInsights, start_time: float) -> FinalReport:
        print("[Stage 3: Report Agent] Drafting executive report deliverable...")
        time.sleep(0.3) # Simulated latency
        total_time = time.time() - start_time
        return FinalReport(
            title="State of AI Agent YouTubers & Builders",
            executive_summary=insights.summary_verdict,
            scored_breakdown=insights.candidate_scores,
            wall_clock_time=round(total_time, 2)
        )

    def run(self, user_prompt: str) -> FinalReport:
        start = time.time()
        print(f"\n[Pipeline Start] Ingress prompt: '{user_prompt}'")
        
        # Step 1: Research
        ctx = self.stage_1_research(user_prompt)
        
        # Step 2: Analysis (Context Handoff)
        insights = self.stage_2_analysis(ctx)
        
        # Step 3: Report (Insights Handoff)
        report = self.stage_3_report(insights, start)
        
        print(f"[Pipeline Complete] Finished in {report.wall_clock_time}s (Additive latency)")
        return report

if __name__ == "__main__":
    pipeline = SequentialPipeline()
    report = pipeline.run("Research the best AI builder on YouTube")
    print(f"\n--- {report.title} ---")
    print(f"Summary: {report.executive_summary}")
    print(f"Scores: {report.scored_breakdown}")
