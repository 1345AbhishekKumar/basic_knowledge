Agent teams: a leader plans, defined specialists run parallel

Like Deep Research. The user prompts a leader agent. The leader thinks what makes a thorough report, then defines teammates 1–5 in parallel. Scouts search, then report back. The team lead reconciles dissent into one deliverable — you keep full control of who does what.

Pattern (Leader → Scouts)

  • User → Leader: leader thinks what makes a thorough report
  • Leader defines 5 teammates in parallel — dev tools, automation, indie, non-English, founder
  • Each scout = Web Search with a lens; all run simultaneously
  • Scouts report back → Leader synthesizes strategy editor report

Deep Research Twin

  • Deep Research also uses a supervisor + sub-researchers
  • But DR adds clarification + research brief as ceremony
  • Teams skips that — “workers doing things in parallel” immediately
  • Both keep the boss as reconciler of differing opinions

Watch Outs

  • Token burn if scouts over-search — 90k before guidance, 15k after
  • Needs human to define roles well; vague brief → vague spread
  • Terminal UI is minimal vs Kimi’s polished streaming panels
  • Best when you want the org chart to run exactly as you drew it
Explanation — control by pre-definition

Teams: the leader thinks, defines, then reconciles

Transcript (Claw Code, Feb, Claude Opus 4.6): “Claw is basically using a leader agent first to process this new prompt and then the leader agent is going to think what can it do to make this such a thorough and nice report… You can define a few agents in parallel at the same time… The leader agent has control over all of them just like the deep research agent.” The key verb is define. You — not the model — decide that Scout 3 is “non-English founder content” and Scout 5 is “founder building in public.”

Reading the architecture

Team Lead (coral) is the only focal orchestrator. Its top edge fans five attach points (≥12px apart per the 6 connector rules) so no two dispatch strokes share a start point. The solid muted strokes down are “DEFINE ×5” — control. The dashed returns are “REPORT BACK” — results, not control. The final coral stroke to Strategy Editor Report is synthesis. The bottom annotation quotes the observed token trace: 70–90 tools → 90k tokens before feedback, 10 tools → 15k after “Don't overthink. 4 channels max, min tool usage.” That feedback loop is drawn as a dashed coral back-edge because it is human steering, not autonomous spawning.

Why Sean says “very similar” to Deep Research — but not the same

  • Similar: both use a supervisor that delegates to sub-researchers and then reconciles dissent into one deliverable. Both keep batch powers: search, download, file ops in parallel.
  • Different: Deep Research adds clarification + research brief as ceremony. Teams skips them — the leader starts dispersing workers immediately. That is why Teams feels faster to start but requires you to have done the decomposition beforehand.

Choose Teams when…

  • You are the CEO/board and need the org to run exactly as drawn
  • Workflow is deterministic: you know the five lenses before execution
  • You need token discipline and can steer scouts down to min tool usage

Watch outs

  • Scout 3 soloing non-English explains why it was slow — lens choice has latency cost
  • Terminal UI is minimal vs Kimi’s streaming panels — harder to audit mid-flight
  • If you cannot name the five lenses, Teams will reproduce your vague prior, just in parallel

Try it

Re-run the YouTube prompt but change the five definitions to your own market: e.g., “Teammate 3: Spanish hands-on builder only, 3 tools max.” Compare token count and see the report shift — that is the control Teams gives you.
