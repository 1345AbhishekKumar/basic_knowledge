File Systems, Metadata & Block Storage

Learn how the operating system kernel organizes, secures, and indexes data through file systems, metadata attributes, block storage allocation, and platform-specific file systems (NTFS, ext4, APFS).

📂 1. The Three Core Components of File Handling

When an operating system manages files on storage media, it coordinates three distinct layers:

1. File Data

The raw binary content of the file (text, pixels, video frames, machine code bytes) written physically across storage media.

2. File Metadata

The structural descriptor containing file properties: creation date, last modified timestamp, owner ID, security permissions (ACLs), file size, and extension.

3. The File System

The database and data structure (directory hierarchy, index table, journaling engine) that maps human-readable paths to physical storage sectors.

🧱 2. Block Storage Architecture

How Data Blocks Function

Operating systems do not store entire files in one contiguous, unbroken strip of disk space. Instead, files are partitioned into uniform chunks called data blocks (or clusters, commonly 4 KB). These blocks are distributed across available sectors on the storage medium.

  • High-Speed Access: The file system can read multiple blocks simultaneously through parallel I/O channels.
  • Space Utilization: When a file is updated or expands, the OS simply assigns new available blocks anywhere on disk, eliminating the need to physically rearrange other files.

🏷️ 3. File Metadata & Extensions

Metadata provides the operating system with the complete contextual profile of any file without needing to parse the full file content:

Metadata Field Technical Purpose & IT Relevance
Creation & Modification Timestamps Tracks when files were written or altered; crucial for incremental backup software and security audit forensics.
Access Control Lists (ACLs / Permissions) Specifies which user accounts and groups have Read, Write, or Execute privileges.
File Size & Allocation Records exact byte size and number of allocated storage blocks on disk.
File Extensions (.ext) Appended suffix (e.g. .docx, .jpg, .exe) telling the OS which default program should open the file.

💾 4. Major Operating System File Systems

File System Operating System Key Characteristics & Capabilities
NTFS (New Technology File System) Windows (Default) Features journaling (prevents data corruption during sudden power loss), granular file permissions (NTFS ACLs), BitLocker encryption support, and volume shadow copies.
ext4 (Fourth Extended Filesystem) Linux (Default) Rock-solid stability, journaling engine, support for 1 Exabyte volumes, backward compatibility with ext2/ext3.
APFS (Apple File System) macOS & iOS Modern 64-bit architecture, native strong encryption, space sharing, and instantaneous file cloning. Replaced legacy HFS+.
FAT32 & exFAT Cross-Platform (Universal) Universal compatibility across Windows, Mac, and Linux. FAT32 has a 4 GB single-file limit; exFAT removes this limit for high-capacity SD cards and USB drives.
