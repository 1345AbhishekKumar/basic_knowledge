Process Management, Scheduling & Virtual Memory

Explore the distinction between static programs and executing processes, how the kernel process scheduler enables multitasking via CPU time slices, and how virtual memory paging overcomes physical RAM limitations.

⚡ 1. Programs vs. Processes

A Program (Passive Code on Disk)

A static set of compiled instructions stored on persistent secondary storage (e.g. chrome.exe or /usr/bin/bash). It consumes disk space but does not actively execute or use CPU cycles.

A Process (Active Instance in RAM)

An actively executing instance of a program loaded into system RAM. The OS kernel assigns each process a unique Process ID (PID), dedicated memory address space, and scheduled CPU time.

Multiple Instances of a Single Program

A single program can have multiple independent processes running simultaneously. For example, opening three separate browser windows or tabs spawns three isolated process instances, each with its own PID and memory allocation.

⏱️ 2. Process Scheduling & Time Slices

Even though modern computers seem to run hundreds of programs simultaneously, a single CPU core can only execute one machine instruction at a time. The kernel creates the illusion of seamless parallelism through preemptive multitasking:

  • Process Scheduler: A core kernel algorithm that decides the order, priority, and duration for each process to run on the CPU.
  • Time Slices (Quantums): Microscopic intervals of CPU time (often 10 to 50 milliseconds) allocated to a process before the scheduler automatically suspends it and switches to the next process (context switching).
  • Manual Process Intervention: When a buggy or rogue application freezes and monopolizes 100% of CPU time, an IT specialist can intervene using task managers (Task Manager in Windows, Activity Monitor in macOS, kill -9 <PID> in Linux).

🧠 3. Memory Management & Virtual Memory

Why Virtual Memory is Critical

Physical RAM is fast but limited in capacity. Virtual Memory simulates additional RAM by combining physical RAM with dedicated space on secondary storage (called Pagefile.sys in Windows, or a Swap Partition/File in Linux).

Memory Paging & Swapping

The kernel divides memory into uniform blocks called pages (commonly 4 KB). When physical RAM fills up, the kernel identifies inactive background pages and writes them to the disk swap space, freeing up high-speed RAM for active foreground applications.

Disk Latency & Thrashing

Because storage drives (even fast NVMe SSDs) are thousands of times slower than physical RAM, excessive swapping causes noticeable latency. If RAM is severely exhausted, the system enters thrashing, spending more time moving pages back and forth than executing useful work.

IT Troubleshooting: "The Computer is Slow!"

When users report sluggish system performance, IT support specialists must diagnose which subsystem is bottlenecked:

  • CPU Deficiencies: Utilization pinned at 100% due to background loops or excessive active threads.
  • Memory Deficiencies: RAM fully consumed, forcing continuous virtual memory disk swapping.
  • I/O Bottlenecks: Storage queue depth saturation or slow network adapters blocking data reads/writes.
