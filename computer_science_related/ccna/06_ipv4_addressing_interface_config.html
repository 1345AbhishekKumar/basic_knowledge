Lesson 06: IPv4 Addressing, Subnets & Interfaces

Master 32-bit IPv4 addressing, Class A/B/C/D/E classifications, usable host capacity formulas ($2^H - 2$), Cisco router interface provisioning, status verification (Up/Up), interface error counters, and the 14-field IPv4 packet header.

🔢 1. IPv4 Address Architecture & Classes

An IPv4 address is a 32-bit logical identifier structured into four 8-bit octets expressed in human-readable dotted-decimal notation (e.g. 192.168.1.254). Each octet spans binary 00000000 (0) to 11111111 (255).

Class 1st Octet Range Default Mask (CIDR) Network / Host Bits Usable Host Capacity
Class A 1 – 126 255.0.0.0 (/8) 8 Net / 24 Host $2^{24}-2 = 16,777,214$
Loopback 127.0.0.0/8 255.0.0.0 (/8) Reserved Internal local TCP/IP stack testing (127.0.0.1)
Class B 128 – 191 255.255.0.0 (/16) 16 Net / 16 Host $2^{16}-2 = 65,534$
Class C 192 – 223 255.255.255.0 (/24) 24 Net / 8 Host $2^8-2 = 254$
Class D 224 – 239 N/A Multicast Reserved for Multicast subscriber groups
Class E 240 – 255 N/A Experimental Reserved for Research / Experimental use

📐 2. Subnet Math & Determining Usable Host Ranges

Within any IPv4 subnet, two critical addresses cannot be assigned to end hosts or router interfaces:

1. Network Address (Host Bits All 0s)

The very first address in the subnet. Identifies the network in router routing tables. (e.g., 192.168.1.0 for a /24 network).

2. Broadcast Address (Host Bits All 1s)

The very last address in the subnet. Used to send data to all hosts on the local network segment. (e.g., 192.168.1.255 for a /24 network).

💡 Usable Host Formula: 2^H - 2

• First Usable Host IP: Network Address + 1 (e.g. 192.168.1.1)
• Last Usable Host IP: Broadcast Address - 1 (e.g. 192.168.1.254)
• Total Usable Hosts: $2^H - 2$ (subtracting the Network ID and Broadcast ID).

⚙️ 3. Cisco Router Interface Configuration

Unlike switch interfaces which are active by default, Cisco router interfaces are in an administratively down shutdown state by default and require an explicit no shutdown command:

Configuration Step Cisco IOS Command Syntax Description
1. Global Config Mode Router# configure terminal Enter device configuration mode.
2. Select Interface Router(config)# interface GigabitEthernet 0/0 Enter interface configuration sub-mode (shortcut: int g0/0).
3. Set IP & Mask Router(config-if)# ip address 192.168.1.1 255.255.255.0 Assign Layer 3 IPv4 address and netmask.
4. Optional Description Router(config-if)# description Uplink to SW1-Core Add operational documentation label.
5. Enable Port Router(config-if)# no shutdown Bring interface Layer 1 and Layer 2 states to UP.
6. Bulk Range Config Router(config)# interface range fa0/5 - 6, fa0/9 - 12 Configure multiple non-consecutive interfaces simultaneously.

📊 4. Verification: show ip interface brief & show interfaces

The primary diagnostic command for Cisco interfaces is show ip interface brief:

Status (Layer 1 Physical) Protocol (Layer 2 Data Link) Engineering Interpretation & Root Cause
Up Up Operational (Up/Up): Physical cable link detected and Layer 2 framing/keepalives active.
Administratively down Down Disabled: The port has the shutdown command applied. Enable with no shut.
Down Down Physical Fault / Unplugged: Cable disconnected, bad patch lead, remote device powered off.
Up Down Data Link / Framing Mismatch: Clock rate missing on serial links, encapsulation mismatch (HDLC vs PPP), or duplex mismatch.

⚠️ 5. Interface Error Counters (Runts, Giants, CRC)

Inspecting show interfaces [interface] reveals hardware counters used for physical troubleshooting:

Runts (< 64 Bytes)

Frames smaller than the IEEE 802.3 minimum of 64 bytes. Caused by Ethernet collisions on half-duplex links or faulty NICs.

Giants (> 1518 Bytes)

Frames exceeding standard maximum Ethernet MTU (1518 bytes without VLAN tag). Indicates babbling node or MTU size mismatches.

CRC Errors (Failed Checksum)

Frames that failed the mathematical FCS polynomial check. Strongly indicates physical noise, bad crimping, damaged copper, or EMI.

Input / Output Drops

Frames dropped due to interface buffer congestion when line rate exceeds device forwarding buffer capacity.

Figure 6.1: Detailed 32-Bit Word Layout of the 14-Field IPv4 Packet Header.
Field Bit Length Description & Key Rules
Version 4 bits Always binary 0100 (4) for IPv4 packets.
IHL 4 bits Header length in 4-byte words. Value of 5 = $5 \times 4 = 20$ bytes (minimum). Maximum is 15 = 60 bytes.
DSCP / ECN 6b / 2b QoS classification (voice priority) and Explicit Congestion Notification.
Total Length 16 bits Entire packet size in bytes (L3 Header + Payload). Maximum is 65,535 bytes.
Identification 16 bits Unique sequence identifier helping receiving hosts reassemble fragmented packets.
Flags 3 bits Bit 0: Reserved (0). Bit 1: DF (Don't Fragment). Bit 2: MF (More Fragments) (1 on all fragments except the last).
TTL (Time To Live) 8 bits Hop counter decremented by 1 at every router hop. When TTL reaches 0, the router drops the packet and sends an ICMP Time Exceeded message to prevent infinite routing loops!
Protocol 8 bits Identifies upper layer payload: 1 = ICMP, 6 = TCP, 17 = UDP, 89 = OSPF.
Header Checksum 16 bits Validates L3 header integrity only (recomputed at every hop because TTL changes).

📝 8. CCNA 200-301 Official Quiz & Knowledge Check

1. Which bit pattern in an IPv4 header is always set to 4 in binary for IPv4 packets?
A. 0001
B. 0110
C. 0100 (Correct)
D. 0010
Explanation: The Version field is 4 bits in length and contains 0100 (decimal 4) for all IPv4 packets.
2. Which field in an IPv4 header will cause a packet to be dropped by a router if it reaches a value of 0?
A. Time to Live (TTL) (Correct)
B. DSCP
C. IHL
D. Header Checksum
Explanation: TTL (Time To Live) is decremented by 1 at each router hop. When it reaches 0, the packet is discarded to prevent permanent loops.
3. How are bit corruption errors in an IPv4 packet's encapsulated payload data detected?
A. The IPv4 Header Checksum field checks the payload
B. The encapsulated Layer 4 protocol (TCP/UDP) checksum checks for payload errors (Correct)
C. Errors in payload data cannot be detected
D. The IHL field verifies payload integrity
Explanation: The IPv4 Header Checksum only verifies the Layer 3 IP header. The encapsulated transport layer protocols (TCP and UDP) utilize their own checksums to validate the payload data.
4. Which bit in the IPv4 Flags field will be set to 1 on all packet fragments except the last fragment?
A. Don't Fragment (DF) bit
B. More Fragments (MF) bit (Correct)
C. Reserved bit
D. Fragment Offset bit
Explanation: The More Fragments (MF) bit is set to 1 for all preceding fragments and 0 on the final fragment.
5. SW1 is trying to autonegotiate speed/duplex with SW2. However, autonegotiation is disabled on SW2's interface (configured statically for 100 Mbps Full Duplex). What settings will SW1 adopt?
A. Speed 100 Mbps, Duplex Full
B. Speed 100 Mbps, Duplex Half (Correct)
C. Speed 10 Mbps, Duplex Full
D. Port enters err-disabled state
Explanation: When the remote peer has autonegotiation disabled, Cisco switches can sense physical electrical speed (100 Mbps) but cannot negotiate duplex, defaulting safely to Half Duplex (creating a duplex mismatch).
