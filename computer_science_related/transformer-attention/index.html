Self-attention: how transformers make words talk to each other

Every modern large language model is built from transformer blocks, and the engine inside each block is self-attention. It is the mechanism that lets the word "it" find the word "animal". This lesson shows you that mechanism — the query, key and value vectors, the score, and the weighted sum — and lets you point a word at a sentence to watch it happen.

No install, no server — opens in your browser. Sources: sources.md.

Part 1 · The hook

Why a single word needs the whole sentence

Read this: "The animal didn't cross the street because it was too tired." What does it refer to? You knew instantly: the animal. Now think about what a computer would need to answer that — it has to look at every other word and figure out which one it points back to. That word isn't stored "inside" it; the meaning has to be assembled from context.

Older models (RNNs) did this by reading left to right and carrying a running memory — which meant word 1's meaning had to survive a long chain of steps to reach word 10, and every step waited for the one before it. The transformer does something radically simpler: it processes all words in parallel, and lets each word look directly at every other word, in one step, with a learned sense of what deserves attention. That one idea — attention — is why transformers train so fast and why the models you use today are all transformers.

Common confusion: attention is not a "search box" over a fixed memory of facts. The model has no lookup table of meanings. It has learned vectors per word, and attention is arithmetic on those vectors — which you're about to see.

Part 2 · The build-up

One mechanism, four moves

1 Every word gets three roles: Query, Key, Value

Start with the word's embedding — a vector that encodes its meaning (512 numbers in the original 2017 model, learned during training). Before attention runs, the embedding is multiplied by three learned matrices, producing three smaller vectors (64 numbers each) that give the word three roles in the conversation:

"animal"
→ × WQ
Query q
→ × WK
Key k
→ × WV
Value v
  • Query — "what am I looking for?" Each word asks this of the whole sentence.
  • Key — "what I advertise / what category am I?" Keys are what queries get matched against.
  • Value — "my actual content." If a query matches my key, my value gets passed along.

Analogy that sticks: query = the word you type into a search engine, key = the titles of the pages, value = the page content. Attention scores titles against your query, then blends the content of the best matches.

2 Score every word against the query: the dot product

For the word being processed (the query word), take its query vector q and dot it with every word's key vector k. The dot product measures how well aligned the two vectors are — the raw attention score. It can be any real number: big and positive for "this is what I need", near zero or negative for "not relevant".

score(it, animal) = qit · kanimal

If it's query happens to point in the same direction as animal's key, the dot product is large, and it "notices" animal. Nothing knows yet — these are just numbers.

3 Scale, then soften: ÷√dₖ and softmax

Long vectors produce large dot products, and huge numbers push the softmax (step 4) into a region where its gradients are tiny and learning stalls. So scores are divided by √dₖ — the square root of the key-vector dimension. In the 2017 model, dₖ = 64, so scores are divided by 8.

softmax scores = softmax( scores ÷ √dₖ )

Then softmax squashes each row of scores into attention weights: positive numbers that sum to 1. A word that scores 5× higher than its rivals ends up with most of the probability mass; a word that scores near zero gets almost nothing. This is where "how much do I care about each word" becomes a clean distribution.

4 Blend: the output is a weighted sum of values

Multiply each word's value vector by its attention weight and add them all up. The result is a single new vector for the query word — its context-aware representation. If it gave 55% of its attention to animal, then it's new vector is mostly animal's content with the rest of the sentence mixed in quietly. Downstream layers can now read the referent straight out of it.

output(it) = 0.55·vanimal + 0.05·vit + …

Common confusion: the output is not the value of the single best-matching word. It is a weighted blend of every word's value. The best match simply dominates the blend.

5 Many heads, order, and the rest of the block

Repeat the whole thing 8× in parallel
h₁h₂h₃ h₄h₅h₆ h₇h₈

Each head has its own Q/K/V projections, so it can learn a different notion of relevance — one head may track coreference ("it" → "animal"), another syntactic position. Outputs are concatenated and projected back.

  • Order matters — but attention doesn't know it. Swap "the dog bit the man" into "the man bit the dog" and the words are the same set, so the attention pattern would be identical. That's why the model adds a positional encoding — a pattern added to each word's embedding that tells the model where the word sits.
  • The rest of the block: each attention result is added back to its input (residual connection) and normalized, then pushed through a small feed-forward network, also residual + normalized. Stack six such blocks and you have the original encoder.
  • Decoders differ slightly: when generating, a word may only attend to words before it — future positions are masked out (set to −∞ before softmax, so they get zero weight).

Part 5 · Summary

Summary

  • Self-attention lets every word look directly at every other word in one parallel step — no sequential chain, which is why transformers train fast.
  • Each word is projected into three vectors: Query (what it's looking for), Key (what it offers), Value (its content).
  • Attention = softmax(Q·Kᵀ ÷ √dₖ)·V: dot queries with keys to score relevance, scale to keep gradients healthy, softmax into weights that sum to 1, then blend values.
  • The output for a word is a weighted blend of the whole sentence's values — "it" comes out carrying "animal".
  • Order isn't free: positional encoding adds it back in. And 8 parallel heads give the model 8 different ideas of relevance at once.
